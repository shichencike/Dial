1. 测量口径 为什么这套数字可比

外部统一墙钟计时；单次进程内重复 N 次自校准以摊薄启动开销；扣除 noop 启动基线后除以 N 得单次纯计算耗时；极快项或被编译器常量折叠成空操作的项统一钳到 5µs 计时下限（如 C 的 b20 字符串拼接可能被 -O2 折叠）；28 项 × 4 语言校验和逐项一致作为正确性锚点；雷达图 6 轴按各维最优语言归一化到 100（越小越好 → 越靠外越优）。

基准说明：C = 1.00×（绝对比值 = 该语言耗时 / C 耗时）。所有维度均「越小越好」； 表格中 ★ 标记 标出该项最优语言。 「产物体积」对编译型语言为可执行文件字节、对解释型 Python 为源码字节； 「编译耗时」对 Python 记为 py_compile 生成字节码的耗时 —— 这两列的口径差异已在下表注明。
† 标记：该项耗时触及 0.005ms 计时下限（或被编译器常量折叠成空操作，如 C 的 -O2 对 b20 字符串拼接）， 此时绝对值是下限而非实测、对应比值会偏大，仅作定性参考，不参与严谨横向比较。

4. 六维工程能力雷达图 4 语言叠加，越靠外越优

6 个轴的量纲不同，无法直接画在一起，因此先做归一化： 每个维度取 4 语言中的最优（最小）值为满分 100，其余语言得分 = 最优值 ÷ 自身值 × 100。 于是「越靠外 = 该维度越接近最优」。速度、内存、编译、启动、体积、源码行数六个方向 各自独立评分，Dial 的轮廓以加粗描边突出。

读图提示：得分是「相对本组 4 语言最优者的百分比」，不是绝对性能分； 例如编译耗时轴上 C 的编译远比 Dial 的 LLVM + LTO 快，Dial 在该轴得分就低， 但速度轴上 Dial 与 C 接近原生。六边形面积可作综合直觉，但各轴权重相等、 不代表任何特定场景下的真实取舍，请结合第 2 节的绝对值一起看。
