更新日志 / Changelog

本文件记录 Dial 语言编译器 dialc 的每个发布版本的相对变更。

版本号规则（强制）

  1. 最多两位小数的单一十进制数：v0.1、v0.2、…、v0.9、v0.91、v0.92…… 不再使用语义化版本的「主.次.修订」三段式。 唯一例外是第三位的补丁号（如 v0.98.1）：它是「两位小数版本 + 一位修复补丁位」， 而非「第三位连续小数」；仅用于修复发布（只修缺陷、不加新特性）， 适用条件见 README §23 第 6 条。
  2. 版本标题一律带 v 前缀、不写补丁位：写作 [v0.91]，不是 [0.91.0]。 （源码 Cargo.toml 的 version 字段受 Cargo 限制仍写作 0.91.0，那是存储格式， 文档与官网一律显示为 v0.91。） 带补丁位的版本例外：补丁发布写作 [v0.98.1]，补丁位必须显示—— 否则读者无从判断自己装的是不是修复过的版本。
  3. 版本号必须严格按时间递增，绝不许倒流：后发版本的日期不得早于先前版本。

详见 README §23。

[v1.04] — 2026-11-06

主题：FFI 成为语言一等公民。 详见 README §33。

版本定位：v1.0 里程碑已在 [v1.03] 达成、标签 v1.0 已打并推送； [v1.00] ~ [v1.03] 是「达成 v1.0」过程中的分版记录（见下方里程碑大标题）。 [v1.04] 是里程碑达成之后的第一个增量分版，不归入上面那批分版记录。 按本轮交付约定：只做本地提交，不推送 GitHub、不打 tag。 本版后续还并入了「语言层动态链接」「工程工具链增补」「DWARF 调试信息（-g）」 「性能基准（4 语言 × 28 维）」与「真实程序缺口补齐（B/C 组，第一批）」 （见 README §34、§35、§36、§37）， 均不新增分版记录，编译器版本 1.4.0 保持不变。 最后一批起 STDLIB_ABI 5 → 6（新增 dial_eprint_* / get_or 等导出符号， 按既有判据递增，见 §37.6）；术语「绝不引入全局变量」统一为 「绝不引入可变全局状态」，并把「函数名重载」「闭包」写入永久否决（§37.1–37.2）。

Added

  • 语言层 extern fn：直接写在 .dial 源码里，编译期生成 LLVM 外部声明、 链接期由 C 编译器解析，不再强制绕 .diali → .a → .dialpkg → install → import。 现有包机制完整保留、行为不变（见 README §15）。
  • 语言层 link "...";：显式链入用户 C 扩展库。相对路径以源文件所在目录为基准解析。
  • 语言层动态链接：link 除静态归档外也接受 .so / .dll / .dylib （含 libx.so.1 带版本号变体），按扩展名校验 ELF \x7fELF / PE MZ / Mach-O 32、64 位或 fat magic；ELF / Mach-O 自动注入 -Wl,-rpath,<库目录>， 产物无需手工设 LD_LIBRARY_PATH。PE 无 rpath，.dll 需放 exe 同目录或 PATH。
  • extern struct（C ABI / repr(C)）：字段顺序、对齐、padding、sizeof 与 C 完全一致； 只经 rawptr<Struct> 读写字段，不按值传递、不能用 StructLit 构造。
  • .diali 类型白名单打穿：byte / bytes / rawptr<T> / fn(A, B): R 全部放行； 形参表改为按顶层逗号切分，嵌套泛型/函数类型签名不会被切坏。
  • 完整数据总线：string.as_c_str() / bytes.as_ptr() 返回借用的 rawptr<byte> （由 C Runtime 跳过 8 字节长度头，用户不写 +8 offset hack）； string_from_cstr(p) / bytes_from_ptr(p, n) 从 C 缓冲区复制出受 ARC 管理的新对象。
  • C 回调：Type::FnPtr 生成标准 C calling convention，C 侧可安全调用 Dial 具名函数； 跨回调状态经 rawptr<void> 显式透传，无闭包、无隐藏环境对象。

  • 新增 dialc check / fmt / test / new / list / uninstall / pack / help 八个子命令； build / run / check / test 共用同一条前端流水线（main.rs::frontend()）；
  • 本地源码模块：import "./util.dial"; 或裸名 import "util";（同目录存在 util.dial 即视为本地模块），递归合并编译，带循环引用 / 同名函数 / 缺失文件诊断；
  • 顶层 test "名" { ... } 块：dialc test 逐块独立进程运行、--filter 筛选， 测试代码不进 build 产物（刻意不新增 test 关键字，避免破坏已有标识符）；

Changed

  • 所有 Dial 函数的 LLVM 签名统一为 C ABI 宽度：bool 内部 i1 → 边界 i32（C 默认整型提升）， byte 内部 i64 → 边界 i8（C 的 uint8_t）；函数体内部仍是 i1 / i64，逻辑零改动。 函数入口 / 出口 / 调用点 / HOF thunk / spawn thunk 五处做对称 abi_adapt 转换， 靠 A–P 全量回归兜底。这是「C 能安全调用任意 Dial 函数」的前提。

Added

一等函数指针 fn(A, B): R - Type::FnPtr 底层就是 LLVM ptr（纯代码地址）：函数名可直接作右值、可赋值 / 传参 / 返回 / 存变量；cb(x) 走精确签名的间接调用（LLVM 18 的 build_indirect_call），参数个数与类型编译期校验； - 没有闭包：无环境对象、无 Fn / FnMut / FnOnce 分类、无匿名函数语法； 回调要带状态必须显式传 rawptr<void>，裸指针生命周期由用户自己负责； - 不受 ARC 管理、无堆分配、无需释放：drop(cb)、print(cb)、 with cb as p { } 都在编译期拦下并给出明确指引； - spawn 首参仍要求顶层具名函数（线程 thunk 需按目标函数静态生成），但函数指针 可以作为普通回调参数传递；相关诊断与注释里「Dial 没有一等函数」的旧表述已同步。

同类型变参 ...xs: T - 在 semantic.rs 的 analyze 开头做 AST 脱糖：形参变成 xs: T[]，调用点尾部 实参打包成带元素类型标注的数组字面量；之后的类型检查 / LSP / codegen 只看得见 一个普通数组； - 严禁隐藏类型标签 / 装箱 / 运行期分派；...xs 必须是参数列表最后一项， 不能与默认实参共存，元素类型须能作为数组元素； - 拒绝异构：sum(1, "a") 编译期报「元素类型不一致」并引导「显式定义结构体或 自定义类型包」； - 变参数组是普通 ARC 数组：函数形参进入时 retain、退出时 release；调用点的临时 数组由编译器在调用结束后插入 release（20 万次调用峰值 RSS 1348 KB，无泄漏）。 绝不能把裸指针的「手动释放」规则套到变参数组上。

extern fn 的 C 风格异构变参（FFI 特例） - .diali 声明支持末尾 ...：extern fn demo_vprintf(fmt: string, ...): int;， LLVM 侧声明为 varargs 函数； - 固定参数仍做严格类型检查，尾部参数按 C ABI 直传（bool 的 i1 会 zext 成 i64， int / char / byte 本就是 i64、float 本就是 f64）； - 只属于包 FFI，Dial 自身函数永远走同类型脱糖；无隐藏类型标签 / 装箱。

stdlib 高阶数组方法（接受回调） - arr.map(f[, state]) / arr.filter(f[, state]) / arr.sort_by(cmp[, state])； - 回调签名固定带 rawptr<void> 状态参数，状态由 C 运行时透传回回调（无闭包）； - C 侧新增 dial_array_hof，只做遍历 / 建数组 / 插入排序；回调经编译器生成的 精确签名 thunk 间接调用（8 字节位模式 ↔ 类型值适配），C 完全不知道回调类型； - 仅支持标量元素（int / float / bool / byte / char）；sort_by 用插入排序而非 qsort，因为后者的比较器拿不到 fn_raw / state，无法透传状态。

[v1.02] — 2026-11-05

底层控制三件套：goto + 标签、with 资源作用域块、裸指针 rawptr<T>。

三样互为因果：goto 是底层清理的利器，但无限制乱跳会把程序打崩，因此配三条死锁； 死锁之一是「不得跳出 with 块」，所以要先有 with；而 with 要能自动释放裸指针， 于是裸指针必须先落地。

本版继续守住项目铁律：不引入 GC；ARC 所有权语义不退化；零隐式转换 （裸指针与 ARC 容器之间、裸指针与裸指针之间都没有隐式转换）。

Added

with 资源作用域块 - 两种等价写法：with 资源 as 名 { ... } 与 with 名 = 资源 { ... }； - 块末自动释放：file → close、thread → join、裸指针 → raw_free； - 覆盖全部出口（正常落穿 / return / break / continue / throw），且互斥地各执行一次 ——它直接复用既有的 defer 机制，而不是另发明一条出口路径； - 块内已显式 close / join / free 的，块末跳过（二次 fclose 是 UB）； - 只管「需要显式释放」的资源：ARC 句柄用 with 是多余的，编译期直接拒绝。

goto 与标签 - label 名字: + goto 名字;，标签函数内唯一，允许向前 / 向后跳； - 三条死锁（编译期硬拦）： ① 禁止跨过变量初始化（Zig 式严格，两个方向都禁；向前跳会读到未初始化的变量， 向后跳会重复初始化并泄漏前一份）。判定用全局深度优先语句序号而非同块下标， 因此「从内层块跳到外层标签、跳过外层声明」也被拦下（实测那是真实的 UB：print(x) 会打印栈上垃圾值）；② 禁止跳出 / 跳进 with 块（否则自动释放被绕过 或重复）；③ 禁止跨越 try 边界（try 依赖 setjmp/longjmp 保存栈帧，跨界跳转会毁掉 jmp_buf，不同 try 块之间互跳同样禁止）； - 另三条边界一并拦下：目标标签未定义、标签重复定义、跳进嵌套块（那里面的变量尚未初始化）； - 跳到外层块的标签时，被跨越的若干层作用域照常清理（defer 按 LIFO 触发、 ARC 句柄逐个 release）——这正是 goto 作为「底层清理利器」的价值。

裸指针 rawptr<T> - 核心红线：绝对不受 ARC 管理——编译器不 retain、不在作用域结束时释放； drop(p) 对裸指针的唯一作用就是 free； - 与 ARC 容器、裸指针之间都没有隐式转换：取 string 的字节缓冲区必须显式 ptr_cast<rawptr<byte>>(s)，换视图必须显式 ptr_cast<rawptr<int>>(p)； - ptr_cast 从 string / bytes 取到的是数据缓冲区的借用（原对象仍受 ARC 管理， 原对象释放后该指针即悬垂——使用者的责任）； - 指针算术显式且带类型：只有 p.offset(n)，步长由元素类型决定； rawptr<void> 无元素大小，禁止算术（须先 ptr_cast）； - 解引用宽度按元素：byte / bool 1 字节、char 4 字节、int / float / 句柄 8 字节； - &x 只允许对可变的栈上值类型变量取址：对 let 取址会绕过不可变约束 → 拒绝； 对堆对象取址拿到的只是槽位地址 → 拒绝； - 配套运行时：dial_raw_alloc（分配失败 Fail-Fast，绝不返回 NULL）/ dial_raw_free。

包的不透明句柄（Type::Opaque）补齐文档与诊断 - 沿用既有 type Db;（.diali 声明），不新增语法、不新增运行时； - 明确契约：与裸指针同属「不受 ARC 管束」的一类——编译器不 retain / release、 作用域结束不释放，必须由包自己的 close / free 手动释放；与 ARC 容器之间 无隐式转换；不可打印；与 rawptr<T> 的区别写清（具名无布局 / 带元素类型可解引用）； - drop(db) 由「静默 no-op + 误标变量已转移」改为编译期报错并给出指引 （此前 drop 对不透明句柄什么都不做，却会禁用该变量，容易让人误以为资源已归还）； - 作为数组 / 通道元素时按 RC 类别 retain / release，文档明确「包作者须保证句柄 布局与 dial_rc_* 兼容」这一责任边界。

[v0.99.1] — 2026-11-03

本版是 v0.99 的修复发布（补丁位）：只修缺陷，不含任何新特性， 所有基于 v0.99 的程序无需改动即可运行（行为完全一致）。

Fixed（修复）

  • a[i] = v 下标赋值在 COW 守卫上误判，导致每次赋值都深拷贝整个数组： 数组运行时在「独占」路径（refcount == 1）上多做了 retain，又在「共享」路径 （refcount > 1）上漏掉了对旧 buffer 的 release——与 dial_map_put 已有的 正确写法（独占时原样移交所有权、共享时克隆并释放旧引用）相悖。 于是每写一次下标赋值引用计数就 +1，COW 守卫 refcount > 1 从此恒真： 每一次 a[i] = v 都深拷贝整个数组。
  • 后果：a[i] = v 循环 N 次即需 O(N²) 内存。实测 100 万次写需约 8 TB， 进程被 OOM Killed（sys 时间高达 3 秒）；同一程序修复后峰值约 10 MB、 耗时 0.01 秒。
  • 根因定位手段：在 dial_array_set 入口用 gdb 读 ((int64_t*)a)[-1]， 可见引用计数在 2 → 1 → 2 → 1 → 2 之间震荡（数组明明由槽位独占持有）。
  • 修复：dial_array_set 与 grow（push 路径）改为与 dial_map_put 完全同款的 所有权交接——独占时原样返回、不 retain 不 release；共享时克隆并 release 旧 buffer。
  • 附带修复：覆盖槽位时改为先 retain 新元素、再 release 旧元素。 原顺序在「旧元素 == 新元素」（如 a[0] = a[0]）时会把计数打到 0（free）， 紧接着又对已释放内存 retain —— use-after-free。
  • dial_array_clone 在独占数组上泄漏元素的引用计数：旧实现对「与原数组同一块 buffer 的别名」也调用 retain_elems，等于把同一批元素的引用计数凭空 +1， 而数组释放时只释放一次——元素引用计数净多 1，永久泄漏。 现 clone() 一律产出独立副本（先 retain 迫使深拷贝，再抵消该次 retain）。
  • 嵌套下标赋值 m[i][j] = v 的所有权结算错位：内层数组是从外层数组元素槽 借来的指针，其那一份引用属于外层数组；若内层 set 按「消耗引用」的语义 处理，会与外层的元素替换重复释放同一份引用。现新增 dial_array_set_borrowed （不消耗被借的引用，改为交出「一份新拥有」的引用），并在 codegen 中按 「消费者释放、变量槽转移」的规则结算。

  • dial_rc_clone 恢复纯粹语义：唯一持有者时原样返回、不再 +1； 多持有者时深拷贝。过去那个 +1 让 clone() 只能靠「别名 + 多一个计数」实现， 是元素引用计数泄漏与 COW 守卫误判的共同源头。 配套地，dial_string_clone / dial_bytes_clone 改为强制深拷贝产出独立副本 （否则纯语义下 b = s.clone() 会让 b 悬垂）。

  • 误拒合法程序 + 三处堆悬垂 + bytes[] 被拒 + 两处安全缺陷（本轮一并修复）：

  • ① select 分支里 move_to 外层变量被误报「已转移」：check_moved_stmt 的 Stmt::Select 分支既不做「只查 arm.chan」的纪律，反而又对 arm.body / default_body 递归了一遍 check_moved_stmt，与 check_stmt 的递归重复—— 同一条 move_to 被检查两次，第二次必然报「变量已转移」。现删掉分支内的递归， 只保留对 arm.chan 的 check_moved_expr（分支体仍由 check_stmt 递归各自检查， 恰好一次）。
  • ③ 结构体字面量 / 字段读取 / 字段赋值的堆字段未 retain：Expr::StructLit、 字段读取（t = p.name）、字段赋值（p.name = s）在写堆类型字段时只 store 不 retain，字段于是成了来源的别名；来源出作用域被 release 后字段即悬垂 （use-after-free，读到的长度字段可能是垃圾，打印出成片乱码）。现统一引入 retain_if_borrowed：借来的值（变量 / 字段 / 数组元素 / get·at）retain 一份， 自带所有权的值（字面量 / clone 等）直接接管。
  • ③ 的同族泄漏：a[i] = <字面量>、a.push(<字面量>)、a.set(i, <字面量>)、 数组字面量元素在循环里逐次泄漏一份引用（容器 retain 了元素，字面量自带的 那一份所有权却没移交）。现引入 settle_fresh_value：自带所有权的值在容器接管后 归还其临时所有权，借来的值则不释放——嵌套下标赋值 m[i][j] = v 也按同一规则结算。
  • ④ bytes[] 被 is_array_elem_type 拒绝：语义层漏收 Type::Bytes，但 codegen 的 array_elem_kind 早已把 Bytes 归为 kind=1（RC），两层不一致。现补上 Type::Bytes（dial_bytes_retain / release 内部即 dial_rc_*，完全兼容）。
  • ⑤ IR 验证失败不中止编译：module.verify() 失败只 eprintln 后继续 emit_object，可能产出无效 IR 或带未定义行为的机器码。现改为直接以易读文字 return Err(...) 中止。
  • ⑥ curl --proto '=https,http' 与「只允许 https」声明矛盾：https URL 可被 302 重定向到 http，中间人攻击窗口重新打开。现 --proto 仅放行 https（本机地址 经 http_allowed 判定才加 http），并新增 --proto-redir 限制重定向协议。

LSP 规范符合性：只用标准形状，不自定义扩展

按 LSP 3.17 规范逐条核对实现，查出并修掉两处形状偏离（此前它们是「按自己的理解」写的）： - textDocument/formatting 的结果：规范规定是 TextEdit[] 本身，此前返回的是 { "edits": [...] } —— 那是私自定义包装，客户端按规范解析会拿到对象而不是数组。现改回数组。 - WorkspaceEdit 的形状：规范原文「若客户端既不支持 documentChanges 也不支持 workspace.workspaceEdit.resourceOperations，那么只有 changes 里的纯 TextEdit 是被 支持的」——所以用哪个形状由客户端能力决定，不能我们单方面决定。 现按 workspace.workspaceEdit.documentChanges 能力二选一：声明了就发 documentChanges （并如实填客户端给的文档版本号，未打开的文件按规范填 null），没声明就回退 changes。

诊断错误码不是「私自扩展」：规范对 Diagnostic.code 的定义是 integer | string， 注释为 "The diagnostic's code, which usually appear in the user interface."—— 码值由语言服务器自定，规范不设中央码表（故 dialc. 前缀命名空间化即可）； Diagnostic.data 的定义更是直接点名用途："A data entry field that is preserved between a textDocument/publishDiagnostics notification and textDocument/codeAction request."—— 我们用 data.package 把包名从诊断带到 quickfix，正是这个字段的设计用途。

符合性从此是自动检查的：冒烟测试新增一张返回形状对照表，逐个方法核对响应结构与 规范一致（Hover 要 contents、CompletionList 要 isIncomplete+items、formatting 必须是 TextEdit[]、SelectionRange[] 只能有 range/parent 两个键……）， 并额外验证「客户端没声明 documentChanges 能力时正确回退到 changes」。 已做负向验证：把 formatting 改回违规形状，三处断言同时报错。

另修正文档残留：README §18 的「十二组 / A→L」「十一组 / A～K」全部更正为 「十三组 / A～M」并补上 M 组与两道新检查；§2 目录结构同步。

诊断：错误码 + 定位 + 缺包不再静默

  • 诊断带稳定错误码（LSP 的 code 字段）：dialc.lex / dialc.parse / dialc.sema / dialc.package.missing。消息是给人看的、码是给工具看的——工具按码处理， 不必去匹配消息文本（措辞会随版本调整，改一次就废掉一个工具）。
  • 缺包的诊断终于报出来了（此前被静默吞掉）：import 了一个未安装的包， 编辑器里毫无任何提示——用户只能去命令行才知道少了什么。现在会明确报出 dialc.package.missing，定位到那句 import，并附带结构化的 data.package。 连带好处：轮 4 的「安装这个包」quickfix 终于真的会触发（此前它只在冒烟测试里 被合成诊断触发过，真实场景下从不出现）。
  • 语义错误的定位落到出错的那条语句上（旧行为是落在文件开头）。表达式 Expr 目前不带位置，故精确度到语句级；但「哪条语句错了」这个信息我们本来就有， 不该浪费。顺带统一了两个位置助手（原先所有权检查那条路径漏了 if/while/for 等语句变体，会退回文件开头）。
  • 代码动作改按错误码匹配（不再靠匹配消息文本），并优先从 data.package 取包名——结构化数据不必再从自然语言里抠。

Fixed（修复）

  • 能力协商把「没声明」误判成「不支持」（轮 1 引入，本版才被自家测试抓到）： negotiate_capabilities 原按「客户端有没有逐项点名」判断能力，于是发 capabilities: {} 的 客户端（不少最小客户端都这么发）会一个能力都拿不到——仓库自带的 tests/lsp_features.py（K 组）当场失败。 现改为按「客户端有没有提到这一段」判断：压根没提 textDocument / workspace 段 = 没表达偏好 → 全开； 提到了该段却漏掉某项 = 明确不支持 → 不广播。 （多广播一个用不上的能力零代价；少广播则让功能静悄悄消失，用户查不出原因。）
  • selectionRange 不认规范形状：LSP 规定 textDocument/selectionRange 用 positions（数组，可多选）， 真实客户端（VS Code）发的就是这个形状；旧实现只认单数 position，于是真实客户端根本拿不到结果。 现按规范收数组、返数组，同时保留单数形式（老客户端不至于拿到数组而崩）。
  • LSP 协议流被裸文本污染 → 编辑器卡死（本版最严重的一个）： resolve_imports() 是 CLI 构建与 LSP 诊断共用的函数，其中两处 println! （「包 'x' v…」「链接 x -> …」）会把纯文本写进 stdout——而 stdout 跑的正是 LSP 的 Content-Length 分帧协议。客户端一旦读到裸字节，分帧立刻错位：症状不是报错，而是卡死 （编辑器在等一条永远对不上的消息）。触发条件却极常见：打开一个 import 了已安装包的文档。
  • 修复：resolve_imports() 改为日志出口由调用方注入（log: &mut dyn FnMut(&str)）， 函数本身不再有资格写 stdout；CLI 构建传 stdout，LSP 传 window/logMessage 通知（编辑器可见、协议合法）。
  • 加固一（动态）：冒烟测试新增协议流纯净性断言——stdout 上出现任何非协议字节即判失败； 并给每次请求加超时看门狗，服务器卡死会快速失败并指名道姓，而不是把 CI 挂死。
  • 加固二（静态）：新增 tools/check_lsp_stdout_purity.py——LSP 用到的库模块与被 LSP 调用的函数里 出现 println! 即失败（CI 独立步骤 + tests/run_tests.sh M 组双重把关）。

Added（新增）

  • dialc install <URL>（阶段 2）：包可以直接从 URL 装，不用先手动下载。
  • 只允许 https://（本机 localhost / 127.0.0.1 / ::1 例外，供本地镜像与自测）。 明文 http 能被中间人改写，而 SHA256 挡不住「换了内容还带着正确哈希」的伪造， 因此非本机地址一律拒绝——宁可装不上，也不降级到明文。
  • --sha256 <哈希>：钉死整个下载物的哈希，用来证明「这就是我要的那一份包」。 比对发生在解压之前，不符即失败；下载物随即删除。
  • 没给 --sha256 也能装，但会明确提示这次只验了「包内文件与 manifest 是否一致」 （能发现残缺与篡改），没验整包来源——不静默降级。
  • 下载用外部 curl 而非引入 Rust 的 HTTP 库：编译器本来就依赖外部工具链 （zig cc / clang / ar），下载器属同一类依赖，不新增「运行期还要装个东西」的负担； 引入 TLS 栈（rustls 等）会显著拉长编译时间与依赖树，与 §21「不引入无用依赖」相悖。 TLS 绝不手写——证书校验、主机名校验、重定向全部交给 curl 背后的成熟实现。
  • 临时文件成功失败都删，~/.dial/packages/ 里不留残骸。
  • 解压前整包校验（阶段 2 的安全底座，src/package.rs::verify_archive）： 按包内 manifest.txt 登记的 SHA256，把包里每个文件验一遍， 一个字节都还没落到磁盘——这是 ARCHITECTURE.md §5.1「校验先于一切 / 每个文件都要校验」 的字面实现。此前 dialc install（本地文件）完全不做校验， 哈希只在编译时对用到的那两个文件验；现在安装这一步就拦下了。 未在 manifest.txt 登记哈希的文件一律拒绝——无法校验的文件不允许进入缓存。

收尾补丁（包安装三条硬规则）

进入 v0.95（LSP 增强）前的收尾，全部落在 src/package.rs 与 §25.6.1， 并由新增的 J 组测试锁死：

  1. 重复安装：~/.dial/packages/<name>/ 下已存在同名包时，先读旧 manifest.txt 比对 abi。 - ABI 相同 → 整目录删除后重新解压（覆盖，避免残留旧机器码 / 旧 .diali）； - ABI 不同 → 报错并拒绝，提示先 rm -rf ~/.dial/packages/<name>/ 再装， 防止不兼容二进制悄悄链入。拒绝「同名不同 ABI 共存」——import 只凭名字引用，共存会重新打开版本冲突的口子。
  2. 强制静态库：targets 映射的库文件后缀必须为 .a（Linux/Termux）或 .lib（Windows）， 形如 .so / .dll 的动态库在解析 manifest.txt 时当场拒绝。 理由：Dial 产物契约是「只链 libc，绝不引入运行时动态依赖」（§3.4 产物依赖契约）， 动态库会破坏这条契约并让 ldd 检查（C 组）失效。
  3. 卸载：缓存是纯派生数据，没有 dialc uninstall 命令——直接 rm -rf ~/.dial/packages/<name>/ 即可， 随时可重装。这条与「ABI 冲突报错提示」自洽。

[v0.81] — 2026-10-30

本版补上 v0.8 并发模型唯一的功能缺口：通道的关闭与 EOF （见 README §27.7）。

缺口本身：v0.8 的通道没有 EOF。生产者一旦退出，消费者就永远卡在 recv 上—— 程序不是跑错，而是死锁。也就是说「生产者结束 → 消费者收尾」这个最常见的并发范式 在 v0.8 里根本写不出来。v0.81 让它可以写了。

Added（新增）

  • 内建 close(ch)：关闭通道（幂等），广播唤醒所有阻塞在 send / recv 上的线程。 同时服务于 file 与 channel（二者都是「显式终结」），按实参静态类型分派。
  • 内建 done(ch): bool：已关闭 且 已空 —— EOF 的精确定义，且单调为真， 因此 while (not done(ch)) { r = recv(ch); } 这个循环必然终止。
  • 内建 closed(ch): bool 与 len(ch): int：是否已关闭 / 队列中当前的剩余元素数。
  • 内建 try_recv(ch): T：非阻塞取出，队列空立即返回，绝不等待 （配合 len(ch) > 0 使用；单选消费者下该条件保证必然取到）。
  • C Runtime：dial_channel_close / closed / len / done / try_recv。 closed 标志不设 atomic——因为 done 必须与元素计数在同一互斥临界区内判定， 拆成两个原子读反而会读到不同时刻的状态。

Changed（语义变更）

  • recv 具备 EOF 语义：「已关闭且已空」时立即返回空指针，不再永久阻塞。 未关闭时行为完全不变（既有代码不受影响）。
  • send 到已关闭通道 → Fail-Fast：元素会永久滞留，使 done 永远为假， 消费者的收尾循环永不结束——一次「关了还发」会把 EOF 语义整个废掉。 ReleaseSafe 及以上当场终止；--fast 下关闭该检查。
  • print 一个 NULL string → Fail-Fast：EOF 之后误用取回的值时， 在使用点打印诊断并 ud2，而不是解引用 NULL 变成一次无解释的段错误。
  • 保留名校验补齐：close / closed / len / done / try_recv 不能用作函数名或结构体名（此前 close 虽按名字分派内建却未列入保留表）。

修正的设计回退

  • v0.8 曾刻意不把 close 扩展到 channel，担心「关掉之后变量还在、作用域结束再 release 一次」造成二次释放。复核后确认该担心不成立：close 只置标志 + 广播， 既不释放通道对象也不动引用计数；对象销毁仍只由原子 ARC 归零触发一次。二者职责不重叠。

Added（新增）

  • 类型：thread（线程句柄，显式 join / detach，不受 ARC 管理）与 channel<T>（通道句柄，跨线程共享 → 原子引用计数 ARC）。
  • 内建 spawn(fn, args...)：创建并立即启动线程。所有实参在 pthread_create 之前写进 argcell —— 零竞争窗口，这也是「move_to 到线程」的唯一合法形式。
  • 内建 move_to(x, ch)：编译期 intrinsic，把 x 的所有权移交给通道。
  • 内建 join / detach / channel(cap) / recv(ch)。
  • C Runtime：新增 stdlib/dial_thread.{h,c}（argcell + pthread_create 封装）与 stdlib/dial_channel.{h,c}（有界环形队列 + 互斥量 + 条件变量 + 原子引用计数）。
  • Moved 状态进 Sema：被移交的变量此后读取 / 写入 / 再次转移全部编译期拒绝 （「变量已转移，无法使用」）。标记落在声明该变量的作用域，分支内移交也会被保守拦下。
  • spawn thunk：编译器为每个被 spawn 的函数生成私有 thunk（void f(ptr argcell)）， 按 8 字节槽宽取出实参后调用真函数，并负责释放被移交进来的那一份所有权。
  • 保留名校验：spawn / join / detach / channel / recv / move_to / thread 不能用作函数名或结构体名。
  • 示例：examples/{thread_spawn,thread_scalar,channel_move,channel_thread,channel_array}.dial； 负向用例 19 个（含 move_use_after / move_twice / spawn_non_void_ret / spawn_struct_param / channel_int_elem / fn_named_move_to 等）。

Changed（变更）

  • moved 集合由「变量名」改为「栈槽指针」：变量名会跨作用域 / 跨函数重名，按名字记账 会让同名变量互相误伤（该 release 的被跳过 → 泄漏）。改为按 alloca 槽位记账后天然精确。
  • 结构体字段 ARC 补全：retain_struct_fields / release_struct_fields 此前漏了 Type::Error （与两侧不对称），本次一并补上 Error 与 Channel。
  • 链接：C 编译追加 -pthread、链接追加 -lpthread（glibc ≥ 2.34 已并入 libc，此处为兼容老 glibc）。

设计约束（本版刻意不做）

  • 通道元素只能是句柄（string / int[] / map / error / channel）：标量需装箱， 编译期拒绝。
  • 不支持 move_to 到已启动的线程：那条路必然有竞争，移交只能在 spawn 时完成。
  • 不支持 close(ch) / try_recv / select / 线程池 / 原子类型。
  • 线程入口必须返回 void、禁止 struct 形参；spawn 首参只能是顶层具名函数（Dial 无一等函数）。

验证

  • A/B/D/E/C 五组全绿（新增 5 正向 + 19 负向），C 组产物仍仅依赖 libc（无 LLVM、无额外 .so）。
  • 零隐式负担：hello.dial 产物中不含任何 pthread / dial_channel / dial_thread 符号。
  • 所有权会计压力测试：20 万次「构造 → move_to → recv → 释放」后 RSS 稳定在 1.3 MB 不增长 （若漏释放应约 7 MB），且无 double-free abort。
