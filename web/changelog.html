更新日志 / Changelog

本文件记录 Dial 语言编译器 dialc 的每个发布版本的相对变更。

版本号规则（强制）

  1. 最多两位小数的单一十进制数：v0.1、v0.2、…、v0.9、v0.91、v0.92…… 不再使用语义化版本的「主.次.修订」三段式。
  2. 版本标题一律带 v 前缀、不写补丁位：写作 [v0.91]，不是 [0.91.0]。 （源码 Cargo.toml 的 version 字段受 Cargo 限制仍写作 0.91.0，那是存储格式， 文档与官网一律显示为 v0.91。）
  3. 版本号必须严格按时间递增，绝不许倒流：后发版本的日期不得早于先前版本。

详见 README §23。

[v0.98] — 2026-11-01

本版把 dialc lsp 从「骨架 + 基础增强」打磨到工业级可用，并补齐三套主流编辑器的接入与安装包。

Added（新增）

  • 编辑器插件安装包（三主流）：编译型语言的编辑器支持是必做的苦活，本版落地三套。
  • editors/vscode/：手写 LSP 客户端（无 npm 依赖），build.sh 打包成 dial-*.vsix （code --install-extension 侧载；CI 在 v* 发版时现构建并附到 Release）。
  • editors/neovim/：零依赖，只用 Neovim 内置 LSP 客户端（ftdetect/ + plugin/，拷进 runtimepath）。
  • editors/emacs/：不开发插件——用 Emacs 内置 eglot 原生连 LSP，仅提供 init.el 片段。
  • 其余编辑器（JetBrains / Zed / Sublime 等）只要能启动 dialc lsp 即可接入，不再单独维护插件。
  • editors/README.md：三编辑器总览与能力矩阵。

Changed（变更）

  • LSP 能力协商：initialize 读取客户端 capabilities，按声明动态广播能力（老客户端不报能力也不报错）； 并新增 window/logMessage 自诊断通道（不污染协议流、不进 stdout）。
  • 补全增强：补全项带 textEdit 精确替换范围（修正旧实现「名字重复拼在后面」的 bug）+ sortText 排序（函数/外部函数最前、结构体/不透明类型次之、变量/形参最后）+ . 触发字符。
  • VS Code 插件接通 hover / 跳转定义 / 补全：原扩展仅接了诊断与语义高亮，现补齐三个 provider 转发到 dialc lsp；initialize 发送真实 capabilities；package.json 升 0.98.0。
  • 文档同步：README §28.7（编辑器插件安装包与 LSP 能力清单）、ARCHITECTURE、CHANGELOG 更新； 各编辑器 README 与 web/ 重新生成。

后续轮次（路线）

  • 轮 2：导航（文档符号 / 工作区符号 / 引用查找 / 重命名 / 签名帮助）
  • 轮 3：编写辅助（格式化 / inlay hint / 补全增强）
  • 轮 4：高级（codeAction / folding / selection / documentLink）

[v0.97] — 2026-10-31

本版把 Dial 从「仅 Linux x86_64」扩展到三平台原生构建——各平台均为 CI 在对应宿主上 直接编译（编译期目标即运行期平台，无交叉编译 ABI 陷阱）：

平台 包 slug 编译器运行依赖 用户程序
Linux x86_64 linux-x86_64 系统 libLLVM-18.so（动态 glibc） 仅依赖 libc
Windows x64（MinGW） windows-x86_64 同目录 LLVM-C.dll（随包分发） 单文件 .exe，无外部依赖
Termux aarch64（musl） termux-aarch64 无（musl 全静态） 单文件，无外部依赖

Added（新增）

  • 三平台 CI 构建与发布流水线（ci.yml）：build-linux / build-windows / build-termux 三个作业各自原生构建，打 v* 标签时由 release 作业把三个平台的 dialc-v<版本>-<slug>.zip 一并上传到 GitHub Release。
  • Windows（MinGW / x86_64-pc-windows-gnu）：使用官方 MSVC 构建的 LLVM 18 全量包， 但只取 C 接口（LLVM-C.lib 导入库 + LLVM-C.dll 运行期）。纯 C ABI 跨 MSVC / MinGW 无名字改写冲突，因此 dialc.exe 直接用 MinGW 目标链接它，无需自编译 LLVM。
  • 配套 tools/llvm-config-win-shim.c：由 MinGW gcc 编译成真正的 llvm-config.exe， 把 LLVM 当 C 接口暴露给链接器（--libnames 只返回 LLVM-C.lib），屏蔽官方 MSVC llvm-config 的怪癖（它运行期依赖包内并未提供的 LLVM-18.dll）。 必须是 .exe 而不是 .cmd/.bat：llvm-sys 先尝试 llvm-config.exe、再尝试裸名， 而 Windows CreateProcess 对不带扩展名的程序名只补 .exe，批处理垫片永远不会被找到。
  • 用户程序由 MinGW gcc + winpthreads 编译，stdlib 的 pthread 代码零改动即用 （winpthreads 提供兼容层），产物 -Wl,-Bstatic -lpthread 静态链入 winpthreads → 单文件 .exe。
  • Termux aarch64（musl 全静态）：在 GitHub 原生 ARM64 runner（ubuntu-24.04-arm）上的 Alpine aarch64 容器内构建（不用 QEMU——QEMU 用户态模拟在新 runner 上会报 Could not open '/lib/ld-linux-aarch64.so.1'）。rustup 装 aarch64-unknown-linux-musl 宿主工具链，llvm18-static 提供静态 LLVM，配合 RUSTFLAGS="-C target-feature=+crt-static -C linker=gcc -C link-arg=-static -C link-arg=-lgcc -C link-arg=/usr/lib/libffi.a" → 完全静态、零外部依赖的 dialc（实测：无 INTERP 段、无 NEEDED，约 118 MB）。
  • 配套 tools/llvm-config-static-linux.sh（只静态垫片）：inkwell 启用的是 llvm18-1-prefer-dynamic，llvm-sys 会主动优先 --libnames --link-shared、把 LLVM 动态链成 libLLVM.so；垫片对 --libnames --link-shared 返回非零码，迫使 llvm-sys 回退到 --link-static。（llvm-sys 并没有 LLVM_SYS_<ver>_STATIC 之类的环境变量可覆盖该偏好。）
  • -lgcc 与 libffi.a 都是补链接缺口：静态 LLVM 组件引用的 __clear_cache 在 libgcc.a； 系统库种类取自 build script 自身的 cfg!(target_feature="crt-static")（宿主而非目标）， 若不处理会残留 NEEDED libffi.so.8，而 Termux 上没有它 → 执行即 not found。

Changed（变更）

  • src/codegen.rs：emit_object 的 CPU 不再写死 "x86-64"，改为按宿主架构推导 （x86_64→x86-64、aarch64→generic），aarch64 也能出正确机器码。
  • src/package.rs：host_triple() 改用编译期 cfg! 宏推导（Windows→x86_64-pc-windows-gnu、 aarch64+musl→aarch64-unknown-linux-musl、aarch64→aarch64-linux-gnu、x86_64-linux→x86_64-linux-gnu）， 保持与既有测试 / 包清单键兼容。
  • src/main.rs：link() / output_paths() / cc_command() 平台化——Windows 产物补 .exe、 C 编译器候选按平台排序、链接时静态链入 winpthreads；其余平台行为不变。
  • tools/package_release.sh：新增精简的单平台发布打包（替代旧的全量源码包），产出 dialc-v<版本>-<slug>.zip（含 dialc[.exe] + stdlib/ + runtime/ + 许可 + 安装脚本； Windows 包额外附带 LLVM-C.dll）。
  • tools/install-dial.sh / install-dial.ps1：支持 dialc.exe、Windows 下随附复制 LLVM-C.dll； install-dial.ps1 可从 GitHub 最新 Release 拉取本平台资产一键安装。
  • ARCHITECTURE.md §0.1 / §0.2 / §8、README §3.1 / §3.2.1 / §3.4：同步三平台支持说明。

Notes（说明）

  • LLVM 18 必须保留：Alpine 3.22 恰好只提供 llvm18，升版会断 Termux 路线；故 Windows 走官方 MSVC 包 + C 接口，而非 MSYS2（其 mingw64-llvm 现已是 23.x，18.x 已下架）。
  • 路线图 7 阶段已完成 1 / 2 / 3 / 4 / 5 / 7；仅剩阶段 6（纯 MSVC 线程后端）在 MinGW 路线下已非阻塞。 阶段 7（官方标准库 .dialpkg 化）随独立 Release stdlib-v1.0.0 落地，详见下条目。
  • 实跑结果：v0.97 三平台作业全部通过并已发布（run 41253324073，release 作业 success）， 三个资产 dialc-v0.97-{linux-x86_64,windows-x86_64,termux-aarch64}.zip 均已上传。 下载后反向验证：Linux 包编译 hello.dial 输出 Hello, dialc!（产物仅 NEEDED libc.so.6）； Termux 包 readelf 确认 AArch64 / 无 INTERP / 无 NEEDED（真全静态）； Windows 包含 dialc.exe + LLVM-C.dll + install-dial.ps1，CI 冒烟通过。

[stdlib v1.0.0] — 2026-10-31（独立 Release，tag stdlib-v1.0.0）

官方标准库（由 stdlib/ + runtime/ 编译归档而成的 libdial_std.a，被每一个 Dial 程序静态链入） 改造为 .dialpkg 形态，独立发版、与 dialc 编译器解耦，走 GitHub Releases 分发。

Added（新增）

  • stdlib.dialpkg 包：单包含三平台预编译静态库 （lib/x86_64-linux-gnu/libdial_std.a · lib/x86_64-pc-windows-gnu/libdial_std.a · lib/aarch64-unknown-linux-musl/libdial_std.a），manifest.txt 记录 name=stdlib / version=1.0.0 / abi=1 / license=MIT OR Apache-2.0 与各平台机器码 SHA256。
  • stdlib/stdlib.diali：与 declare_stdlib() 逐条对齐的接口签名文件，供 .dialpkg 自描述与校验。
  • tools/build_stdlib.sh：统一选 zig cc/clang/gcc + ar，把 runtime/*.c + stdlib/*.c 编译归档为单份 libdial_std.a（默认 -DDIAL_SAFETY=1 ReleaseSafe 预编译）。
  • tools/make_stdlib_pkg.py：收三平台 .a 与 .diali，算 SHA256、生成 manifest.txt 并打包 stdlib.dialpkg。
  • dialc 链接期自动链入：src/main.rs::link() 优先 package::find_installed("stdlib") 取本平台 .a 链入，日志打印「使用已安装的标准库包: stdlib v1.0.0（ABI 1，目标 …）」； 未安装则回退实时编译 stdlib/ + runtime/ 源码（默认 Debug），任何环境都能编出程序。
  • ABI 兜底：已装包 manifest.abi ≠ package::STDLIB_ABI（新增常量，锁定为 1）即当场报错并给出重装方案 （rm -rf ~/.dial/packages/stdlib 后重装），绝不静默崩溃。
  • 一键脚本自动安装：tools/install-dial.sh / install-dial.ps1 装好 dialc 后静默从 Release stdlib-v1.0.0 拉取 stdlib.dialpkg 并执行 dialc install（STDLIB_RELEASE 可钉版本，离线/失败仅告警）。
  • CI 自动发布：.github/workflows/ci.yml 在 stdlib-v* 标签触发 publish-stdlib 作业， 由 build-linux / build-windows / build-termux 各自产出本平台 .a 后打包发布。

Changed（变更）

  • 预编译安全等级统一为 ReleaseSafe（-DDIAL_SAFETY=1）：C Runtime 层越界/空指针等 UB 由 ud2 Fail-Fast 拦下，兼顾性能与安全；与用户程序自身 --release/--fast 等级是两回事（标准库等级发布时已钉死）。

Docs（文档）

  • ARCHITECTURE.md §8 阶段 7 标 ✅；README §25 新增 §25.10「官方标准库 stdlib.dialpkg（独立发布）」； §25 顶部状态注释同步（URL 安装 / 一键脚本 / stdlib 化均已落地）。

[v0.96] — 2026-10-31

本版补齐 ARCHITECTURE.md §8 实现路线 的阶段 2 剩余部分与阶段 5： 包的来源不再只能是本地文件，也可以是 URL；并新增一键安装脚本， 把「装好 Dial 环境 + 把该装的包装上」变成一条命令。

至此路线图 7 个阶段已完成 1 / 2 / 3 / 4 / 5， 剩余阶段 6（Windows 线程后端）与阶段 7（官方标准库 .dialpkg 化）。

Added（新增）

  • dialc install <URL>（阶段 2）：包可以直接从 URL 装，不用先手动下载。
  • 只允许 https://（本机 localhost / 127.0.0.1 / ::1 例外，供本地镜像与自测）。 明文 http 能被中间人改写，而 SHA256 挡不住「换了内容还带着正确哈希」的伪造， 因此非本机地址一律拒绝——宁可装不上，也不降级到明文。
  • --sha256 <哈希>：钉死整个下载物的哈希，用来证明「这就是我要的那一份包」。 比对发生在解压之前，不符即失败；下载物随即删除。
  • 没给 --sha256 也能装，但会明确提示这次只验了「包内文件与 manifest 是否一致」 （能发现残缺与篡改），没验整包来源——不静默降级。
  • 下载用外部 curl 而非引入 Rust 的 HTTP 库：编译器本来就依赖外部工具链 （zig cc / clang / ar），下载器属同一类依赖，不新增「运行期还要装个东西」的负担； 引入 TLS 栈（rustls 等）会显著拉长编译时间与依赖树，与 §21「不引入无用依赖」相悖。 TLS 绝不手写——证书校验、主机名校验、重定向全部交给 curl 背后的成熟实现。
  • 临时文件成功失败都删，~/.dial/packages/ 里不留残骸。
  • 解压前整包校验（阶段 2 的安全底座，src/package.rs::verify_archive）： 按包内 manifest.txt 登记的 SHA256，把包里每个文件验一遍， 一个字节都还没落到磁盘——这是 ARCHITECTURE.md §5.1「校验先于一切 / 每个文件都要校验」 的字面实现。此前 dialc install（本地文件）完全不做校验， 哈希只在编译时对用到的那两个文件验；现在安装这一步就拦下了。 未在 manifest.txt 登记哈希的文件一律拒绝——无法校验的文件不允许进入缓存。
  • 一键安装脚本（阶段 5）：tools/install-dial.sh（Linux / Termux）与 tools/install-dial.ps1（Windows / PowerShell）。按 §3.2 承担两件事（顺序不能反）： 1. 初始化 Dial 环境：建 ~/.dial/ 目录树（bin / packages / cache/downloads）、 把 dialc 装进 ~/.dial/bin/ 并挂进 PATH、把 stdlib/ 与 runtime/ 一并装到 ~/.dial/、写一份 ~/.dial/config.txt 工具链配置； 2. 自动安装已下载的包：初始化完成后重新扫描找到的 .dialpkg （当前目录及其子目录，或参数指定的目录），逐个执行 dialc install。

    为什么脚本要「自动重新扫描」而不是让用户逐个点名：一键安装的语义是 「我把这个目录交给你，你把该装的都装上」。用户不该需要记住包名、也不该需要 为每个包敲一条命令——包就在那里，脚本看得见。

Fixed（修复）

  • 一键安装后编译器找不到 stdlib/ 与 runtime/：编译器按可执行文件所在位置 向上找这两个目录（target/release/dialc → 工程根）。装到 ~/.dial/bin/dialc 后， 那个位置正好是 ~/.dial/——所以它们必须跟着一起装。 少了这一步，用户在自己项目里编译会报「找不到 stdlib/ 与 runtime/ 目录」， 一键安装等于没装。脚本现已一并安装这两个目录。
  • install 时的 manifest.txt 校验时机：此前 install() 先解压再校验（且当时压根没校验）， 现在先校验后解压。

Added（测试）

  • 测试组 L（tests/pkg_install_url.py，26 项断言）：真起一个本机 HTTP 服务器 真实提供 .dialpkg，用真正的 dialc install <URL> 去装，验证：
  • 正常安装成功；--sha256 与实际一致时也成功；未钉死哈希时给出明确提示；
  • 坏包一律装不进去：内容被篡改（改 .diali 但保留原哈希）、 --sha256 不符、404、非本机的明文 http——四种情形全部失败；
  • 失败后 ~/.dial/packages/ 无残骸（半截的包绝不能留在缓存里）；
  • 装完能 import 并编译运行，输出正确；

收尾补丁（包安装三条硬规则）

进入 v0.95（LSP 增强）前的收尾，全部落在 src/package.rs 与 §25.6.1， 并由新增的 J 组测试锁死：

  1. 重复安装：~/.dial/packages/<name>/ 下已存在同名包时，先读旧 manifest.txt 比对 abi。 - ABI 相同 → 整目录删除后重新解压（覆盖，避免残留旧机器码 / 旧 .diali）； - ABI 不同 → 报错并拒绝，提示先 rm -rf ~/.dial/packages/<name>/ 再装， 防止不兼容二进制悄悄链入。拒绝「同名不同 ABI 共存」——import 只凭名字引用，共存会重新打开版本冲突的口子。
  2. 强制静态库：targets 映射的库文件后缀必须为 .a（Linux/Termux）或 .lib（Windows）， 形如 .so / .dll 的动态库在解析 manifest.txt 时当场拒绝。 理由：Dial 产物契约是「只链 libc，绝不引入运行时动态依赖」（§3.4 产物依赖契约）， 动态库会破坏这条契约并让 ldd 检查（C 组）失效。
  3. 卸载：缓存是纯派生数据，没有 dialc uninstall 命令——直接 rm -rf ~/.dial/packages/<name>/ 即可， 随时可重装。这条与「ABI 冲突报错提示」自洽。

[v0.81] — 2026-10-30

本版补上 v0.8 并发模型唯一的功能缺口：通道的关闭与 EOF （见 README §27.7）。

缺口本身：v0.8 的通道没有 EOF。生产者一旦退出，消费者就永远卡在 recv 上—— 程序不是跑错，而是死锁。也就是说「生产者结束 → 消费者收尾」这个最常见的并发范式 在 v0.8 里根本写不出来。v0.81 让它可以写了。

Added（新增）

  • 内建 close(ch)：关闭通道（幂等），广播唤醒所有阻塞在 send / recv 上的线程。 同时服务于 file 与 channel（二者都是「显式终结」），按实参静态类型分派。
  • 内建 done(ch): bool：已关闭 且 已空 —— EOF 的精确定义，且单调为真， 因此 while (not done(ch)) { r = recv(ch); } 这个循环必然终止。
  • 内建 closed(ch): bool 与 len(ch): int：是否已关闭 / 队列中当前的剩余元素数。
  • 内建 try_recv(ch): T：非阻塞取出，队列空立即返回，绝不等待 （配合 len(ch) > 0 使用；单选消费者下该条件保证必然取到）。
  • C Runtime：dial_channel_close / closed / len / done / try_recv。 closed 标志不设 atomic——因为 done 必须与元素计数在同一互斥临界区内判定， 拆成两个原子读反而会读到不同时刻的状态。

Changed（语义变更）

  • recv 具备 EOF 语义：「已关闭且已空」时立即返回空指针，不再永久阻塞。 未关闭时行为完全不变（既有代码不受影响）。
  • send 到已关闭通道 → Fail-Fast：元素会永久滞留，使 done 永远为假， 消费者的收尾循环永不结束——一次「关了还发」会把 EOF 语义整个废掉。 ReleaseSafe 及以上当场终止；--fast 下关闭该检查。
  • print 一个 NULL string → Fail-Fast：EOF 之后误用取回的值时， 在使用点打印诊断并 ud2，而不是解引用 NULL 变成一次无解释的段错误。
  • 保留名校验补齐：close / closed / len / done / try_recv 不能用作函数名或结构体名（此前 close 虽按名字分派内建却未列入保留表）。

修正的设计回退

  • 内建 spawn(fn, args...)：创建并立即启动线程。所有实参在 pthread_create 之前写进 argcell —— 零竞争窗口，这也是「move_to 到线程」的唯一合法形式。
  • 内建 move_to(x, ch)：编译期 intrinsic，把 x 的所有权移交给通道。
  • 内建 join / detach / channel(cap) / recv(ch)。
  • C Runtime：新增 stdlib/dial_thread.{h,c}（argcell + pthread_create 封装）与 stdlib/dial_channel.{h,c}（有界环形队列 + 互斥量 + 条件变量 + 原子引用计数）。
  • Moved 状态进 Sema：被移交的变量此后读取 / 写入 / 再次转移全部编译期拒绝 （「变量已转移，无法使用」）。标记落在声明该变量的作用域，分支内移交也会被保守拦下。
  • spawn thunk：编译器为每个被 spawn 的函数生成私有 thunk（void f(ptr argcell)）， 按 8 字节槽宽取出实参后调用真函数，并负责释放被移交进来的那一份所有权。
  • 保留名校验：spawn / join / detach / channel / recv / move_to / thread 不能用作函数名或结构体名。
  • 示例：examples/{thread_spawn,thread_scalar,channel_move,channel_thread,channel_array}.dial； 负向用例 19 个（含 move_use_after / move_twice / spawn_non_void_ret / spawn_struct_param / channel_int_elem / fn_named_move_to 等）。

Changed（变更）

  • moved 集合由「变量名」改为「栈槽指针」：变量名会跨作用域 / 跨函数重名，按名字记账 会让同名变量互相误伤（该 release 的被跳过 → 泄漏）。改为按 alloca 槽位记账后天然精确。
  • 结构体字段 ARC 补全：retain_struct_fields / release_struct_fields 此前漏了 Type::Error （与两侧不对称），本次一并补上 Error 与 Channel。
  • 链接：C 编译追加 -pthread、链接追加 -lpthread（glibc ≥ 2.34 已并入 libc，此处为兼容老 glibc）。

设计约束（本版刻意不做）

  • 通道元素只能是句柄（string / int[] / map / error / channel）：标量需装箱， 编译期拒绝。
  • 不支持 move_to 到已启动的线程：那条路必然有竞争，移交只能在 spawn 时完成。
  • 不支持 close(ch) / try_recv / select / 线程池 / 原子类型。
  • 线程入口必须返回 void、禁止 struct 形参；spawn 首参只能是顶层具名函数（Dial 无一等函数）。

验证

  • A/B/D/E/C 五组全绿（新增 5 正向 + 19 负向），C 组产物仍仅依赖 libc（无 LLVM、无额外 .so）。
  • 零隐式负担：hello.dial 产物中不含任何 pthread / dial_channel / dial_thread 符号。
  • 所有权会计压力测试：20 万次「构造 → move_to → recv → 释放」后 RSS 稳定在 1.3 MB 不增长 （若漏释放应约 7 MB），且无 double-free abort。
