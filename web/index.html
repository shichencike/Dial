Dial

一门静态强类型、显式标注、无 GC 的编译型语言。编译器前端把 Dial 源码翻译为 LLVM IR， 所有容器与运行时能力由 C 实现——比 C 更严格，且彼此融洽严谨。

阅读语言规范 查看更新日志
v0.6 当前版本 Rust + inkwell / LLVM 18 零 LLVM 运行时依赖 短路 and / or Fail-Fast 越界即 ud2 / int3 无 GC 内存宪法

静态强类型，无推断

每个变量、参数、返回值都必须显式标注类型。不存在 auto / 类型推导，杜绝隐式行为。

不透明指针契约

string 与 int[] 在 IR 中只是 ptr，用户代码永远无法触碰其内存布局，一切经由 C 导出函数。

C 承担一切容器

字符串、动态数组、哈希表、IO、内存管理全部由 C 实现，Dial 只负责把调用翻译出去。

零隐式转换

int 与 float 之间无隐式提升或窄化，必须显式调用 int_to_float / float_to_int。

短路求值

and / or 与 C 的 && / || 一致短路，保证判空等代码不会因盲目求值而崩溃。

产物零 LLVM 依赖

用户程序只依赖 C Runtime（libc），绝不链接 libLLVM。

无 GC 底线（内存宪法）

永不引入追踪式 GC。确定性内存管理靠 ARC 引用计数 + 编译期逃逸分析/移动语义，未来裸指针坚持「谁申请谁释放」。

哈希表 map（ARC + COW）

v0.4 新增 map 类型（int → int），与 string / int[] 共用同一套引用计数；put 触发扩容或写时复制后由编译器把新指针写回接收变量。

for / else if / break / continue

v0.4–v0.5 新增：for (i in start..end) 半开区间循环、else if 语法糖（编译期展开为嵌套 if）、break 与 continue（for 的 continue 先自增再判条件，不会死循环）。

代码编写纪律

拒绝过度抽象——宁可 WET 绝不 DRY 过头；不引入无用依赖；允许安全与性能的冗余；能用一个循环和一个 if 解决的绝不套设计模式。

Fail-Fast 铁律（v0.6）

宁可当场段错误，绝不产生未定义行为或静默错误数据。越界读写、负下标、整数除零一律当场终止：Debug 发射 int3、ReleaseSafe 发射 ud2，由操作系统接管 Core Dump。

三档安全等级

默认 Debug 崩溃保护全开；--release 保留防 UB 检查但陷阱更精简；--fast 关闭全部检查换取极限性能，等级同时作用于 LLVM IR 与 C Runtime。⚠️ --fast 下的越界将退化为 C 的未定义行为——除非你正在写底层核心算法且确信下标绝不越界，否则永远不要使用它。

快速开始

# 构建编译器（需要本机 LLVM 18）
export LLVM_SYS_181_PREFIX=/usr/lib/llvm-18
cargo build --release          # 产物：target/release/dialc

# 编译并运行一个 Dial 程序
./target/release/dialc run examples/hello.dial

# 端到端自测（正向 + 负向 + 产物契约）
./tests/run_tests.sh

最小示例

fn main(): int {
    let name: string = "world";
    print("hello, " + name);   // 字符串按内容比较，拼接须显式 concat
    return 0;
}
