[CI 修复与 v1.0 标签重打] — 2026-11-06

目标：修掉上一节留下的两个红色测试作业，让 release 作业能真正产出带 stdlib.dialpkg 的 v* Release；随后删除并重打 v1.0 标签触发新发布， 使 releases/latest 指向这个新页面。纯修复，编译器版本 1.3.0 与 STDLIB_ABI 4 均不变。

Fixed

  • Windows 核心冒烟：stdlib/dial_env.c 原先依赖 POSIX 的 srandom() / random() / clock_gettime() / nanosleep()；MinGW-w64 只提供 rand（RAND_MAX 仅 32767），clock_gettime / nanosleep 则靠 winpthreads 才勉强可用，属于脆弱依赖。现改为：
  • 自实现 xorshift64* PRNG（纯 64 位整数运算），一次产出 64 位、掩掉符号位 得到 [0, 2^63) 的非负随机数；三平台行为一致，不再依赖任何 libc 随机函数；
  • dial_now() / dial_sleep() 在 _WIN32 下改用 Win32 原生 GetSystemTimeAsFileTime（FILETIME → Unix 纪元秒）与 Sleep，非 Windows 仍走 clock_gettime / nanosleep。
  • Linux 全量测试：tools/cve_check.py 的 check_110_leak（CVE-2026-DIAL-007） 编译清单漏了 stdlib/dial_array.c，导致 dial_string_split() → undefined reference to dial_array_new，而检测器把「编译 / 链接失败」误判成 「❌ 仍可利用」并阻断发布。补全清单后该用例输出 FIXED（3/3 残留元素已释放）， 全套 8/8 个 CVE 已确认修复。

验证

  • zig cc -target x86_64-windows-gnu 编译 dial_env.c 通过，_WIN32 / __MINGW32__ 宏确认定义，预处理确认选中 GetSystemTimeAsFileTime + Sleep 分支；-target aarch64-linux-musl 与 x86_64-linux-gnu 全量编译链接通过 （zig 裸 windows 目标缺 pthread.h 是验证环境限制，CI 已安装 winpthreads）；
  • bash tools/build_stdlib.sh 全量归档通过；examples/env_demo.dial 端到端输出一致； C 级验证：PRNG 连续 8 次取值互异且非负、now() 在 sleep(12) 后严格增大；
  • python3 tools/cve_check.py --repeat 1 8/8 通过；bash tests/run_tests.sh A–O 全绿。

发布

  • 删除本地与远程 refs/tags/v1.0（该标签此前没有关联任何 Release， CI 的 release 作业因测试作业失败被 skip，删除是安全的）；
  • 在本节修复后的最新提交上重新创建 v1.0 附注标签并推送，触发新的 v* CI： 三平台构建 → release 作业上传 zip / .vsix / stdlib.dialpkg → releases/latest 指向该页面。安装脚本零改动即可生效。
