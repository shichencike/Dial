[v0.98.1] — 2026-11-02

本版是 v0.98 的修复发布（补丁位）：只修缺陷与文档矛盾，不含任何新特性， 因此所有基于 v0.98 的程序无需改动即可运行（行为完全一致）。

Fixed（修复）

  • 裸块作用域 { ... } 从「语法能过、语义/索引崩溃」修到完整可用： Stmt::Block 的 AST 变体在定义与模式匹配两侧不一致（元组 vs 具名结构体）， 导致整个编译器无法编译。现已统一为具名变体 { body, line, col }， 词法/语法/语义/索引/代码生成五处同步打通，裸块可正常引入词法作用域。
  • README §17.2 与 §28 对 LSP 能力的结论自相矛盾：§17.2 仍写「重命名 / 引用查找 / 格式化 未实现」，而 §28 记载这三项已在 v0.98 轮 2 / 轮 3 落地。现按实现统一口径， §17.2 改为「已实现」并指向 §28 对应小节。
  • README §3.2 的交叉引用指错节：注释里的「见 §3.1.2 / §3.1.3」实际指向 Windows x64 与 Termux aarch64，而 Linux 的 LLVM 依赖在 §3.1.1、 动态库要求（LD_LIBRARY_PATH）在 §3.1.5。现改为正确节号。
  • README §2 与官网 spec.html §2 的目录结构里 install-dial.ps1 重复两行 （第二行还少了「支持 irm | iex 一键命令」的说明）。现删去重复行。
  • README §28 标题停在 v0.95：正文已含 v0.98 的四轮工业化与三编辑器接入，标题与内容脱节。 现改为覆盖到 v0.98。
  • spec.html §28.2 与 §28.7.1 对 textDocumentSync 的说法直接冲突： 一处写「声明 textDocumentSync = 1（全量同步）」，另一处写「必须用选项形式 {openClose, change: 1, save}，不能用纯数字 1」。后者才是对的 （纯数字形式没有 save 字段，客户端不会发 didSave，诊断刷新会静默失效）。 现按后者统一。
  • CHANGELOG 缺 v0.98.1 条目：v0.98.1 已实际发布（tag v0.98.1）， 但本文件顶部仍是 [v0.98]。现补上本条目。
  • README §23 的版本号规则与 v0.98.1 冲突：原规则写死「最多两位小数、 不存在三位小数的版本」，而 v0.98.1 是既成事实。现补充第 6 条， 明确补丁位仅用于修复发布（只修缺陷、不加新特性），并规定其边界条件。
  • cve.html 的 CVE 编号年份穿越：项目日期是 2026，编号却写成 CVE-2024-DIAL-001。 现统一为 2026 年，并说明这是项目自建的跟踪编号（非 MITRE 分配的正式 CVE 编号）。
  • README §18 的 CI 关卡表缺 cve_check 一关，而 cve.html 声称 「已在 CI 工作流中接入，作为发布前的强制门禁」。现已核对 CI 工作流确实包含该步骤， §18 的表格补上这一行——文档与实际流水线对齐。

Added（新增）

  • print_raw(s)：原样输出字符串、不追加换行。此前 print(s) 永远在末尾补 \n， 导致任何需要连续输出的程序都写不出来（拼行表格、进度条、逐字动画、协议帧）。
  • write_char(c)：输出单个字符、不追加换行。与 print(char) 的唯一差别就是这个换行符。
  • str(char)：char 纳入 str() 的支持类型，得到 1 字符的 UTF-8 字符串， 可直接参与拼接（str(c) + "!"）。
  • dialc version / dialc --version / dialc -V：显示版本号。 版本取自 Cargo.toml（编译期注入），与全站唯一真相一致。

Changed（变更）

  • print(char) 的换行语义被写进文档：明确 print(char) 输出字符本身并追加一个 \n （行式输出），而 write_char(char) 不追加。此前二者的差别只存在于实现里、没写进文档， 读者无法确定该用哪个。
