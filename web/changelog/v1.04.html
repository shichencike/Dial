[v1.04] — 2026-11-06

主题：FFI 成为语言一等公民。 详见 README §33。

版本定位：v1.0 里程碑已在 [v1.03] 达成、标签 v1.0 已打并推送； [v1.00] ~ [v1.03] 是「达成 v1.0」过程中的分版记录（见下方里程碑大标题）。 [v1.04] 是里程碑达成之后的第一个增量分版，不归入上面那批分版记录。 按本轮交付约定：只做本地提交，不推送 GitHub、不打 tag。 本版后续还并入了「语言层动态链接」「工程工具链增补」「DWARF 调试信息（-g）」 「性能基准（4 语言 × 28 维）」与「真实程序缺口补齐（B/C 组，第一批）」 （见 README §34、§35、§36、§37）， 均不新增分版记录，编译器版本 1.4.0 保持不变。 最后一批起 STDLIB_ABI 5 → 6（新增 dial_eprint_* / get_or 等导出符号， 按既有判据递增，见 §37.6）；术语「绝不引入全局变量」统一为 「绝不引入可变全局状态」，并把「函数名重载」「闭包」写入永久否决（§37.1–37.2）。

Added

  • 语言层 extern fn：直接写在 .dial 源码里，编译期生成 LLVM 外部声明、 链接期由 C 编译器解析，不再强制绕 .diali → .a → .dialpkg → install → import。 现有包机制完整保留、行为不变（见 README §15）。
  • 语言层 link "...";：显式链入用户 C 扩展库。相对路径以源文件所在目录为基准解析。
  • 语言层动态链接：link 除静态归档外也接受 .so / .dll / .dylib （含 libx.so.1 带版本号变体），按扩展名校验 ELF \x7fELF / PE MZ / Mach-O 32、64 位或 fat magic；ELF / Mach-O 自动注入 -Wl,-rpath,<库目录>， 产物无需手工设 LD_LIBRARY_PATH。PE 无 rpath，.dll 需放 exe 同目录或 PATH。
  • extern struct（C ABI / repr(C)）：字段顺序、对齐、padding、sizeof 与 C 完全一致； 只经 rawptr<Struct> 读写字段，不按值传递、不能用 StructLit 构造。
  • 编译期类型内建 sizeof<T>() / alignof<T>() / offsetof<T>(field)：手写 C 库绑定 核对内存布局的刚需。语法与 ptr_cast<T>(x) 共用「类型实参在 <> 里」的约定 （offsetof 的字段名是裸标识符，如 offsetof<Point>(y)）；数值按宿主 target DataLayout 在编译期算出、发射为 i64 常量，零运行时开销；全部返回 int。 三种内建都直接吃 extern struct，与字段读写路径、与 C 的 offsetof 逐字节一致 （已加 P 组 2b 子测试锁死）。void 被显式禁止（sizeof 在 C 里未定义）； offsetof 要求真实存在且类型实参确为结构体（含 extern struct），否则编译期报错。 修复点：模块创建时把宿主目标机的 DataLayout/triple 显式写到 module 上—— 否则 module 默认 DataLayout 会把 i64 对齐写成 4（而非 x86-64 SysV 的 8）， 导致上述内建与 extern struct 字段偏移与 C 不一致。
  • @export：把 Dial 函数导出给 C 调用（见 README §33.9）。 extern fn 是「Dial 调 C」，@export 是「C 调 Dial」——被标注的函数以裸 C 符号名 （无 mangling）与 C 调用约定对外暴露，C 侧可直接链接 / dlsym 调用。两条硬规则： ① 签名必须全是 C 兼容类型（标量 / rawptr<T> / fn(A):R / extern struct 值）， 含 string / bytes / 数组 / map 一律编译期拒绝（C 侧无法按 C ABI 正确接收， 放行等于埋 UB）；② 只有标了 @export 的函数才是全局符号，其余 Dial 函数收成 LLVM Private linkage——模块内照常递归、照常取函数指针，但不导出，既不污染 C 侧 符号空间、也不会与别的目标文件里的同名符号撞车。main 例外，恒为外部可见。 export fn（不带 @）是等价写法。
  • packed struct：网络协议的逐字节对齐（见 README §33.10）。 packed extern struct 走 C ABI 紧凑布局（bool / byte → i8），与 C 的 __attribute__((packed)) / #pragma pack(1) 逐字节一致——网络协议头的字段偏移是 协议硬约定，一个 padding 字节就让整包解析错位；packed struct 则是 Dial 自己 值语义结构体的紧凑布局。布局用 sizeof<T>() / alignof<T>() / offsetof<T>(field) 编译期核对（零运行时开销），P 组 2c 把 Dial 侧的三个数与 C 侧 sizeof / _Alignof / offsetof 逐项比对（刻意不写死期望值——布局随平台变， 「两边相等」才是要锁住的东西）。
  • volatile rawptr<T>：内存映射 IO 的易失访问（见 README §33.11）。 语义与 rawptr<T> 完全一致（同样不受 ARC 管、同样要显式 raw_free），差别只在 代码生成：经它读写的内存发射 load volatile / store volatile，LLVM 不再对其做 任何优化——每次访问都真实落总线。volatile 只能修饰裸指针（volatile int 编译期拒绝）；ptr_cast<volatile rawptr<T>>(p) 把普通内存切进易失视图时 易失性会保留，不在转换处被悄悄抹掉。
  • bitcast<T>(x)：底层内存强转（见 README §33.12）。 把值的位模式按目标类型重新解释——不读、不改内存。类型实参约定与 ptr_cast<T>(x) / sizeof<T>() 同一套。位宽必须相同，不一致一律编译期拒绝 并报出两边实际位宽（位宽按 target DataLayout 现算——32 位平台上指针是 32 位， 那时 bitcast<int>(ptr) 就该被拒）。指针 ↔ 整数走 ptrtoint / inttoptr （LLVM 的 bitcast 本身不允许跨类转），整数 ↔ 整数、浮点 ↔ 整数同位宽互转走 真正的 bitcast。
  • .diali 类型白名单打穿：byte / bytes / rawptr<T> / fn(A, B): R 全部放行； 形参表改为按顶层逗号切分，嵌套泛型/函数类型签名不会被切坏。
  • 完整数据总线：string.as_c_str() / bytes.as_ptr() 返回借用的 rawptr<byte> （由 C Runtime 跳过 8 字节长度头，用户不写 +8 offset hack）； string_from_cstr(p) / bytes_from_ptr(p, n) 从 C 缓冲区复制出受 ARC 管理的新对象。
  • C 回调：Type::FnPtr 生成标准 C calling convention，C 侧可安全调用 Dial 具名函数； 跨回调状态经 rawptr<void> 显式透传，无闭包、无隐藏环境对象。

Changed

  • Dial 函数的链接可见性按 @export 收口：v1.04 之前所有 Dial 函数都是 LLVM 默认的 External linkage，等于每个 Dial 程序都在往全局符号空间里倒函数名—— 既会与别的目标文件里的同名符号撞车，也让「哪些是给 C 用的」无从表达。现在 只有 @export 标注的函数与 main 是全局符号，其余收成 Private linkage： 模块内照常递归、照常取函数指针（传给 C 回调也照常工作），但不导出、不被 死代码消除误删。依赖「Dial 函数能被 C 按名字链接」的代码请补 @export （见 README §33.9）。

  • 新增 P 组：把 C 侧专项库编成 .a，逐项比对 sizeof / offsetof 与 C 完全一致， 验证 Dial↔C 双向字段读写、C 回调状态透传；另编真实共享库做动态链接端到端 （显式 link + extern fn，并用 readelf -d 断言 RUNPATH 已注入），再用伪装的 .a / .so / .dll / .dylib 验证魔数拒绝不是靠「文件不存在」蒙混过关。
  • 新增 Q 组（工程工具链专项）：全部新子命令、A3 非零退出且不产物、fmt 幂等与 token 流不变、test 通过 / 失败 / 过滤、多文件 import 合并与循环 / 冲突 / 缺失诊断、 new → pack → install → import → uninstall 全链路闭环、pack 拒绝动态库与缺字段、 A7 运行时位置断言。回归脚本由 A–P 扩为 A–Q（后续由 R 组扩为 A–R，见下）。
  • 新增 R 组（DWARF 调试信息专项）：llvm-dwarfdump 核对 .debug_info / .debug_line 段与 add / main / a / b / sum / counter / note 七个 Dial 名字、行表含 .dial 源文件；真实 gdb -batch 在 .dial:9 断点断言 print counter = 42、 bt 显示源码行；无 -g 不产 Dial 调试符号的负向断言、-g --fast 兼容断言。 环境缺 gdb / llvm-dwarfdump 时对应子项明确跳过（⏭️）而非误报失败， 保证 CI 不被工具缺失阻断。回归脚本由 A–Q 扩为 A–R。
  • 性能基准与 CI 集成（v1.04 增补）：build-linux 作业新增 Go 安装与 「性能基准采集」步骤，实跑 4 语言编译 + 28 项计时 + 112 校验和一致性， 生成 CI 机器上的数据/网页并经 check_bench_data.py 校验，同时验证仓库内 交付快照（bench/data.json + web/bench.html）配套；产物上传为 bench-4lang-28dim artifact。CI 只写 /tmp 再上传，绝不回写 web/bench.html， 避免机器相关的实测数据让官网同步校验误报。
