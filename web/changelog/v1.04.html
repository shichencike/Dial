[v1.04] — 2026-11-06

主题：FFI 成为语言一等公民。 详见 README §33。

版本定位：v1.0 里程碑已在 [v1.03] 达成、标签 v1.0 已打并推送； [v1.00] ~ [v1.03] 是「达成 v1.0」过程中的分版记录（见下方里程碑大标题）。 [v1.04] 是里程碑达成之后的第一个增量分版，不归入上面那批分版记录。 按本轮交付约定：只做本地提交，不推送 GitHub、不打 tag。 本版后续还并入了「语言层动态链接」「工程工具链增补」「DWARF 调试信息（-g）」 「性能基准（4 语言 × 28 维）」与「真实程序缺口补齐（B/C 组，第一批）」 （见 README §34、§35、§36、§37）， 均不新增分版记录，编译器版本 1.4.0 保持不变。 最后一批起 STDLIB_ABI 5 → 6（新增 dial_eprint_* / get_or 等导出符号， 按既有判据递增，见 §37.6）；术语「绝不引入全局变量」统一为 「绝不引入可变全局状态」，并把「函数名重载」「闭包」写入永久否决（§37.1–37.2）。

Added

  • 语言层 extern fn：直接写在 .dial 源码里，编译期生成 LLVM 外部声明、 链接期由 C 编译器解析，不再强制绕 .diali → .a → .dialpkg → install → import。 现有包机制完整保留、行为不变（见 README §15）。
  • 语言层 link "...";：显式链入用户 C 扩展库。相对路径以源文件所在目录为基准解析。
  • 语言层动态链接：link 除静态归档外也接受 .so / .dll / .dylib （含 libx.so.1 带版本号变体），按扩展名校验 ELF \x7fELF / PE MZ / Mach-O 32、64 位或 fat magic；ELF / Mach-O 自动注入 -Wl,-rpath,<库目录>， 产物无需手工设 LD_LIBRARY_PATH。PE 无 rpath，.dll 需放 exe 同目录或 PATH。
  • extern struct（C ABI / repr(C)）：字段顺序、对齐、padding、sizeof 与 C 完全一致； 只经 rawptr<Struct> 读写字段，不按值传递、不能用 StructLit 构造。
  • .diali 类型白名单打穿：byte / bytes / rawptr<T> / fn(A, B): R 全部放行； 形参表改为按顶层逗号切分，嵌套泛型/函数类型签名不会被切坏。
  • 完整数据总线：string.as_c_str() / bytes.as_ptr() 返回借用的 rawptr<byte> （由 C Runtime 跳过 8 字节长度头，用户不写 +8 offset hack）； string_from_cstr(p) / bytes_from_ptr(p, n) 从 C 缓冲区复制出受 ARC 管理的新对象。
  • C 回调：Type::FnPtr 生成标准 C calling convention，C 侧可安全调用 Dial 具名函数； 跨回调状态经 rawptr<void> 显式透传，无闭包、无隐藏环境对象。

  • 本地源码模块：import "./util.dial"; 或裸名 import "util";（同目录存在 util.dial 即视为本地模块），递归合并编译，带循环引用 / 同名函数 / 缺失文件诊断；

  • B/C 组缺口补齐 第 3 批：语言机制（B7 / B8 / B6），落在 src/parser.rs + src/semantic.rs + src/codegen.rs + runtime/dial_rt_mem.c + stdlib/dial_kvmap.c：
  • B7 文件级只读 const：支持标量 / 字符串 / 数组 / 嵌套数组 / 字符串数组 / 结构体字面量，以及字面量上的常量表达式（可常量折叠）；const 可引用其他 const （解析期内联展开）；顶层 var 全局变量编译期拒绝（禁止可变全局状态红线）； const 重赋值 / 非编译期常量值 / 类型不匹配 / 局部变量遮蔽 const 均被拒。

  • B6 结构体进容器：Point[] 与 map<string, Struct>。值类型结构体装不进 8 字节 数组 / map 值槽，故装箱为引用计数对象（dial_struct_box，布局 [int64 refcount][payload]，与既有 Dial 堆对象同构）后入槽，读出时解箱按值拷贝； put / get / contains / remove / get_or / values() 全通路打通； map 侧新增 KV_STRUCT(6) 值种类（与 KV_STRING 同走 retain/release）， 未命中返回空指针并由编译器还原零值结构体（绝不解引用空指针）。
  • 边界（如实标注）：B6 本批只放开「字段全为标量」的结构体；含句柄字段的 结构体进容器需要字段级 ARC（装箱 / 释放时逐字段 retain/release），该能力尚未 落地，故语义层明确拒绝而非让它「看起来能用」却在释放时泄漏或悬垂。
  • 顺带修好的通用缺陷：字段访问此前只支持「变量 / 字段链」作基对象， Pt{}.x / make().y / arr[i].f 一律报「仅支持对变量/字段进行赋值」；现让 gen_expr 字段分支把非 lvalue 基物化到栈上临时槽再取字段指针 （gen_lvalue_ptr 保持只服务数组元素写，避免破坏 a[i] = v 的写回语义）。 B7 的 const 结构体内联后「取字段」成为常态路径，此修复是其必要前提。
  • V 组回归（新增第 22 组）：B8 / B7 / B6 正向端到端、顶层 var 被拒、 省略无默认值字段被拒、默认值类型不匹配被拒、含句柄字段结构体作数组元素 / map 值被拒；A–U 扩为 A–V。内存专项：3M 次 Point[] 建放、1M 次 map<string,Point> 读写循环均在虚拟内存上限内通过（装箱对象随容器释放，无泄漏）。
  • 本批明确不碰（按裁决划清界限）：B1（impl 方法，暂用 fn 替代）、 B2（用户泛型，死守单态化底线）、B3（枚举 ADT，不引入 Tagged Union）； B5（函数名重载）与 B4（闭包）维持永久否决。C11（http.dialpkg 独立包）待落地。

  • 密码学绝不手搓：TLS 由 mbedTLS 3.6.2 提供并已接线上层 （https:// 走 mbedTLS，证书校验 fail-closed：系统根 + 自定义 CA 双信任链， mbedtls_ssl_get_verify_result() 非 0 即拒绝），gzip / deflate 解压由 zlib 1.3.1 提供； 两者 vendor 进仓库（third_party/，保留上游 LICENSE 与版权声明）， 构建离线可复现；zlib 裁掉 gz*.c（gzip 文件 API，依赖 POSIX lseek， 与 HTTP 内存解压无关且编不过 Windows / musl 目标）。

  • 错误与所有权口径：包不抛 Dial 异常（不假定宿主装了异常栈），失败返回空句柄 （is_null 可判），原因取自线程局部最近错误槽；不透明句柄不进 ARC， 释放必须显式（dial_http_close / dial_http_resp_free）。
  • 链接顺序修正（编译器侧）：静态归档由链接器从左到右扫描，符号只有在其归档 被扫描时仍处于「未定义」状态才会被拉入。包要向 Dial 返回 string / bytes 就必须引用标准库的 dial_string_new / dial_bytes_new，故顺序由 obj → runtime → stdlib → packages 改为 obj → runtime → packages → stdlib。
  • 两条写包必备的 FFI 约定（已写进包内注释）：Dial 的 string 跨到 C 传的是 载荷指针（[int64 len][bytes...]），须用 dial_string_cstr() 取文本； 带缓冲的读取器必须先取缓冲再读 socket，否则会漏掉已吞进缓冲的响应体并误报 「连接提前关闭」。
  • 一处刻意不动语言：Dial 字符串字面量只支持 \n \t \\ \"、不支持 \r， 而 HTTP 行结束符是 CRLF——因此包提供 dial_http_write_line 负责补 CRLF， 不为发一个 HTTP 包顺带改语言。

  • 两条传输：https:// 走 TLS 1.3 + ALPN 协商 h2（未协商出 h2 则 fail-closed 拒绝降级为 HTTP/1.1）；http:// 走明文 h2c prior-knowledge （RFC 7540 §3.4，直发 client preface）。
  • 自研 HPACK（RFC 7541）：请求侧统一用 literal-without-indexing / new name 最简编码（不维护动态表）；响应侧完整实现静态表（61 项）、Huffman 解码（257 项）、 动态表、整数前缀编码与动态表大小更新。静态表与 Huffman 码表由 tools/gen_hpack_tables.py 从 Python hpack 库常量生成，避免手敲出错。
  • 真·并发多路复用：新增会话式 API（dial_http2_connect / dial_http2_request / dial_http2_session_free）。一个 Http2Session = 一条连接， 多个 spawn worker 可共享同一句柄并发提交 stream（客户端 stream id 取奇数）， 帧在单连接上按 stream_id 交错分发。因 mbedTLS 的 ssl_context 不能多线程 并发读写，会话启动时创建唯一 I/O 线程独占 socket/TLS：worker 只入队帧、 在自己的 condition variable 上等待，由 I/O 线程读帧分发后唤醒； DialHttpResponse 在 worker 自己线程里组装，reader 线程绝不构造 Dial ARC 对象。
  • 并发与跨平台：POSIX 用 pthread_mutex_t / pthread_cond_t / pthread_t， Windows 用 CRITICAL_SECTION / CONDITION_VARIABLE / CreateThread； 三平台静态库零警告零错误。为此修正了编译器 spawn thunk 对 Type::Opaque 形参的槽宽：Opaque 已 lowering 成 i8ptr，thunk 必须按 ptr 槽读出， 否则 load 出 i64 传给期望 ptr 的形参会被 LLVM verifier 拒绝。
  • W 组回归新增 HTTP/2 子组（同组第 9 步）：Python h2/hpack/hyperframe 起本地服务器并故意乱序响应，6 个 worker 共享单连接、逐条断言 path == X-Stream（不串台）、conns = 1 / streams = 6、 h2 ALPN 协商成功、no-ca rejected = true、404 / 500 全绿。
  • 宪法裁决入文档（§37）：STDLIB_ABI 5 → 6（make_stdlib_pkg.py 默认、 CI 两处、dialc new 骨架同步，后者改为引用 package::STDLIB_ABI 消除硬编码）； 术语统一为「绝不引入可变全局状态」；「函数名重载」「闭包」写入永久否决； B7（文件级 const 只读常量、禁 var 全局）与 B8（结构体显式默认值、 未声明默认值仍报错）的精确语义先于实现写清；C11 常用库确立为独立 .dialpkg。

Changed

  • 所有 Dial 函数的 LLVM 签名统一为 C ABI 宽度：bool 内部 i1 → 边界 i32（C 默认整型提升）， byte 内部 i64 → 边界 i8（C 的 uint8_t）；函数体内部仍是 i1 / i64，逻辑零改动。 函数入口 / 出口 / 调用点 / HOF thunk / spawn thunk 五处做对称 abi_adapt 转换， 靠 A–P 全量回归兜底。这是「C 能安全调用任意 Dial 函数」的前提。
  • STDLIB_ABI 4 → 5（新增 stdlib/dial_ffi.c 四个数据总线函数）， 编译器版本 1.3.0 → 1.4.0；make_stdlib_pkg.py 默认 --abi 5、CI --abi 5。
  • 系统库（libc / libm）继续由 C 编译器默认动态解析，不进 link、不进 LTO 链路； 所有 .dialpkg 仍强制 .a / .lib 静态归档并校验 ar 魔数 !<arch>\n， J 组三条硬规则一字未动。语言层 link 则静态 / 动态并存：动态库按扩展名验 ELF / PE / Mach-O 魔数并注入 rpath，由源码作者显式承担运行期依赖；不写 link 动态库的程序仍满足「只链 libc」的默认产物契约（测试 C 组照常断言）。
  • 运行时诊断带位置（A7）：panic / assert 失败 / 未捕获异常现在输出 文件:行:列（文件名与行列是编译期常量，运行期零额外开销）；新增 dial_panic_loc / dial_assert_fail_loc 两个 C 入口，旧符号保留给其它调用点。 首行文案与旧版完全一致，G 组回归不受影响。
  • Fail-Fast 收紧（A3）：旧版 dialc build a.dial b.dial 打印「未知参数」后 仍以 rc=0 产出 a 的可执行文件（多余输入被静默吞掉）；现在任何未知参数一律 非零退出，多出来的是 .dial 时附带 §34.2 本地模块写法的指引。同一规则推广到全部新子命令。
  • -g 隐含 O0：emit_object() 在 debug_info 且非 --fast 时用 OptimizationLevel::None，避免默认 O2 把栈槽变量优化成 <optimized out> 而让 print var_name 失效；-g --fast 仍走用户明确要求的 O3 + SIMD/LTO，并打印兼容提示。 安全等级、运行期检查、C Runtime 注入与 .dialpkg 契约均不变。

  • 函数实参类型不匹配的诊断：参数序号此前被误填成形参类型名（显示「第 rawptr 个参数」）， 且泛型类型只显示 rawptr 而非完整签名；现改为正确序号 + Type::display() 完整类型。
