[v0.94] — 2026-10-31

本版落地 dialc lsp 语言服务器骨架（见 README §28）， 把「写代码」这件事的最后一环补上：编辑器里能看到红线、能看到高亮， 而且红线与 dialc build 的报错是同一条错误、同一个位置、同一句文案。

至此用户指定的「开发闭环」三项（char 类型 → import 机制 → LSP 骨架）全部打通。

Added（新增）

  • dialc lsp 子命令：stdio 上的 JSON-RPC 服务（Content-Length 分帧）。 不引入 LSP 框架——骨架只需要「读一条 JSON、写一条 JSON」， 异步运行时与依赖树的代价远超收益。
  • 诊断：didOpen / didSave 时发布；词法 / 语法 / 语义三阶段任一失败即停， 只报第一个错误（与 dialc build 行为一致）。改正保存后自动清空，关文件后不留残留红线。
  • 语义高亮：textDocument/semanticTokens/full，token 由编译器自己的词法器产出 （不另写一套高亮扫描器——一旦有两份词法，高亮与编译必然慢慢分道扬镳）。
  • VS Code 扩展 editors/vscode/：不需要 npm install（LSP 客户端是手写的 200 行）， 拷进扩展目录即可；另附 Neovim 原生 LSP 的三行配置。

Changed（变更）

  • If / While / For / 表达式语句补上位置（此前只有 var / return 这类带）： 所有语句现在都带 line / col，语义诊断因此能落回源码。
  • 语义错误的语句级位置兜底：check_stmt_at 把内部产生的「无位置」错误 盖到出错那一条语句上（只补缺失的，已精确定位的原样放行）。 修掉的是一个真实缺陷：表达式错误原先一律报「第 0 行第 0 列」， 在编辑器里就是第一行一个红点，等于没定位。 B 组负向用例的输出也因此全部带上了「第 N 行第 M 列」。
  • char 参与算术的专门诊断：此前落到通用的「要求两个操作数类型完全相同」那条， 会让人以为补个转换就能做算术。现在单独说明： 'a' + 1 的意图无法判定，请先 char_to_int 再 int_to_char。
  • dialc install 回显包导出函数：装完直接列出 extern fn 签名与其 /// 文档， 不必再去翻 .diali 文件。

Added（测试）

  • 测试组 I（tests/lsp_smoke.py）：真起一个 dialc lsp 子进程按协议往返， 覆盖初始化能力协商、诊断定位到出错那一行、语义 token 的差分解码 + 源码子串反查、 shutdown 后干净退出、以及 stderr 不污染协议流。
  • 其中 UTF-16 换算一条特意用 emoji 而非中文做用例： 中文在 BMP 内（1 char = 1 码元）测不出换算错误，只有 emoji（1 char = 2 码元）能。 已反向验证过：删掉换算代码重跑，确实只有 emoji 那条变红。

刻意未做

补全 / 跳转定义 / 悬停 / 重命名 / 格式化——这些都建立在跨文件符号表之上， 而 Dial 目前一次编译一个文件，没有符号表可查。硬做只能做出「猜」的结果，比不做更糟。

收尾补丁（包安装三条硬规则）

进入 v0.95（LSP 增强）前的收尾，全部落在 src/package.rs 与 §25.6.1， 并由新增的 J 组测试锁死：

  1. 重复安装：~/.dial/packages/<name>/ 下已存在同名包时，先读旧 manifest.txt 比对 abi。 - ABI 相同 → 整目录删除后重新解压（覆盖，避免残留旧机器码 / 旧 .diali）； - ABI 不同 → 报错并拒绝，提示先 rm -rf ~/.dial/packages/<name>/ 再装， 防止不兼容二进制悄悄链入。拒绝「同名不同 ABI 共存」——import 只凭名字引用，共存会重新打开版本冲突的口子。
  2. 强制静态库：targets 映射的库文件后缀必须为 .a（Linux/Termux）或 .lib（Windows）， 形如 .so / .dll 的动态库在解析 manifest.txt 时当场拒绝。 理由：Dial 产物契约是「只链 libc，绝不引入运行时动态依赖」（§3.4 产物依赖契约）， 动态库会破坏这条契约并让 ldd 检查（C 组）失效。
  3. 卸载：缓存是纯派生数据，没有 dialc uninstall 命令——直接 rm -rf ~/.dial/packages/<name>/ 即可， 随时可重装。这条与「ABI 冲突报错提示」自洽。

Docs（文档）

  • §3.1 运行环境要求：明确 Dial 只支持 Linux（x86_64 · 动态 glibc）， 并只在近两年内发布的发行版上验证（Ubuntu 24.04 LTS / Fedora 42 / Debian 13 等）； 明确排除 musl 系统（Alpine 等）——编译器本体与产物都依赖 glibc，跨 ABI 用不了。 列出工具链版本（Rust ≥ 1.80、LLVM 18 开发库、zig cc 或 clang）与运行 dialc 本体所需的 LD_LIBRARY_PATH（仅影响编译器，不影响产物）。
  • §3.2 从源码构建：把流程钉死为 克隆 → 进入（cd Dial，仓库根即编译器本体）→ 编译（cargo build --release）， 并说明仓库根就是 Cargo.toml 与 src/ 所在之处（没有嵌套的 dialc/ 子目录），避免读者多进一层目录。
  • 官网「快速开始」同步加了 Linux/glibc 提示、LD_LIBRARY_PATH 步骤与十组自测命令。
