Added

  • B1「impl 方法块」语言特性落地（README §37.12）：[v1.10] 发布后增量， 这是 v1.04 第三批曾记为「明确不碰——暂用 fn 替代」的能力，本轮真正补上。 让用户 struct 与包不透明句柄（Type::Struct / Type::Opaque，如 GUI 的 GuiWindow / GuiMenu）能写 impl T { fn m(self, ...) { ... } }，调用 obj.m(args) 编译期降级为静态函数调用（self 即首参）——win.draw() 就是 dial_gui_window_draw(win) 的面向对象写法，包 .diali 契约一个字都不用改。
  • 宪法：不新增关键字（impl 走 Ident("impl") + 类型名 + { 识别，与 test 块同例，旧程序把 impl 当变量名/函数名仍合法）；obj.m(args) 与手写 普通函数调用完全同构，编译产物 / ABI 逐字节不变，不碰 STDLIB_ABI、 .diali、C Runtime；旧签名一字不动。
  • 实现（最小侵入、零重复）：parser 把 impl 方法降级为普通顶层 Func （符号名 mangle 成 __impl_T_m，self 注入首参）；语义 type_of 按 obj 静态类型做面向用户的参数校验（诊断显示 T.m、不含 mangle 名、不把 self 计入参数个数，零隐式转换铁律照旧）；codegen gen_method_call 用 make_impl_call 把 Method 就地改写为 Expr::Call 并递归复用整条调用生成链 （签名校验 / 默认实参 / 实参求值 / C ABI 宽度适配 / build_call / 返回值 全部零改动复用）。保持 Method 形态、不做全局 AST 脱糖，故 move / 引用分析 / desugar_expr 等遍历 pass 天然适用、零改动。
  • 容器特例收窄：push / set / put / add 也是内建容器 COW 原地写回 协议名，用 is_impl_receiver 精确排除具名类型接收者，避免同名 impl 方法被 误当成容器方法把返回值错误 build_store 回变量槽；内建容器方法行为一字未变。
  • 现役边界（如实标注，不夸大）：只支持具名类型；self 按值传入副本， 方法内 self.f = ... 不回写调用者（Dial struct 值语义，与 Rust &mut self 不同）；支持默认实参 / 普通形参 / 返回任意类型 / 方法间调用 / 返回结构体再调 方法；暂不支持同类型变参 ...xs（parser Fail-Fast 提示改用 xs: T[]）、 C ABI 导出、关联函数（无 self 的 T::new()）、标量/内建容器/裸指针挂 impl。

  • 回归：新增 AC 组（第 29 组）——tests/impl/impl_struct.dial（self 字段 读写 / 方法间调用 / 返回结构体 / 表达式位置 / impl 作标识符 / 容器 push 同名隔离 / 值语义边界）、impl_default.dial（默认实参）、 impl_gui_handle.dial（包不透明句柄 GuiMenu 方法，无 DISPLAY 纯内存逻辑）、 tests/bad/impl_*.dial 六个 Fail-Fast 负向 + 诊断面向用户断言。 全量 538 ✅ → 549 ✅ / 0 ❌，A–Z + AA + AB + AC 二十九组全绿。

  • int32 / float32 完整一等类型 + FFI 精确 32 位宽度（README §5.8）： 解决「只有 int(i64) / float(f64)，传给按 int32_t / float 读取的 C 侧 时静默读到垃圾数据」这一隐蔽数据损坏。

  • 词法 / AST / 语义 / codegen 全链路新增 int32(LLVM i32) 与 float32(LLVM f32)；值类型、无 ARC、可声明变量 / 参数 / 返回值， 可参与同类算术与比较，可 print / print_raw / str() / 插值。
  • 零隐式转换铁律不变：与 int / float 之间必须显式 int_to_int32 / int32_to_int / float_to_float32 / float32_to_float； 前一条走 C 侧范围校验，越出 int32 值域当场 Fail-Fast，绝不静默截断。
  • FFI 精确宽度：ffi_type_to_llvm / cstruct_field_llvm 按真实 i32 / f32 生成签名与 extern struct 字段；abi_adapt 补 f32 ↔ f64 的 fpext / fptrunc；@asm 输入 / 输出白名单纳入新类型；DWARF 给出 32 位 精确宽度与编码；LSP 语义高亮归入类型关键字。
  • 边界如实标注：int32[] / float32[] 编译期拒绝（8 字节槽位模型）， simd<T, N> 元素仍限原有标量，位运算仍只限 int。
  • 回归新增 AB 组 4 条：tests/ffi/scalar32_probe.c 用真实 int32_t / float 探针，逐项验证参数 / 返回值 / 多参数 / extern struct sizeof=24 与 offsetof=8/12/16 / 双向字段读写与黄金输出逐字节一致； tests/ffi/scalar32_overflow.dial 锁定越界 Fail-Fast（哨兵 9999 不打印）； tests/bad/s32_*.dial 五个负向用例锁定零隐式转换。

Fixed

  • http.dialpkg：chunked 长度行不再静默损坏（§20 Fail-Fast）。dial_http.c 的 dh_read_chunked 用 strtoll(line, &endp, 16) 解析块长度却不检查 endp != line： 服务器返回 xyz 时 strtoll 返回 0 且 endp == line，畸形响应被当成「结束块」， 响应体凭空少一截却报 200。现补四道检查：endp == line（一个十六进制数字都没 解析到）、errno == ERANGE（溢出）、负数、以及长度数字后除 ;chunk-ext / 行尾空白 以外的脏尾随字符；任一命中即 DIAL_HTTP_ERR_PROTOCOL 并把坏行写进错误槽，合法 1a;ext=1 扩展照常放行。errno.h 提到文件顶部无条件包含，Windows 分支同样生效。
  • http.dialpkg：Termux 目标平台能加载系统根证书库。dial_tls.c 的 load_linux_ca 原本只读 /etc/ssl/certs 与 /etc/ssl/cert.pem，而 Termux 的证书在 $PREFIX/etc/tls/cert.pem——文档把 Termux 列为目标平台，https 却直接报 「无法加载系统根证书库」。现按 getenv("PREFIX") 的实际长度动态拼该路径 （绝不静默截断），加载成功即计入受信链；失败时的中文提示同步列出 Termux 路径。 自定义 CA 优先级与 fail-closed 证书校验一点未动。
  • http.dialpkg：额外请求头不再被 512 字节静默截断。dial_http2.c 的 h2_submit 原用 char buf[512] 且 llen 超限就截到 511 字节：很长的 Authorization / Cookie 会被悄悄砍掉，请求照样发出却鉴权失败。现按行长 malloc 整行 （dh_hlist_add 本就拷贝 name/value，用完即释放），分配或入表失败按 Fail-Fast 整条请求失败、不发半截头。HTTP/1.1 侧 dh_request 本就走动态 dh_buf，无此问题。
  • http.dialpkg：HTTP/2 额外头名统一小写化（去掉截断后暴露的协议合规坑）。 RFC 7540 §8.1.2 要求头名必须小写，用户按 HTTP/1.1 习惯写的 Authorization: <超长 token> 会被对端以 ProtocolError 拒绝。现 h2_submit 只把 extra_headers 的头名转小写，H1 侧大小写不敏感、保持原样；.diali 对外签名与 abi = 6 均不变（仅注释补充，pack 时重算 SHA256、install 同 ABI 覆盖）。
