[v0.99.1] — 2026-11-03

本版是 v0.99 的修复发布（补丁位）：只修缺陷，不含任何新特性， 所有基于 v0.99 的程序无需改动即可运行（行为完全一致）。

Fixed（修复）

  • a[i] = v 下标赋值在 COW 守卫上误判，导致每次赋值都深拷贝整个数组： 数组运行时在「独占」路径（refcount == 1）上多做了 retain，又在「共享」路径 （refcount > 1）上漏掉了对旧 buffer 的 release——与 dial_map_put 已有的 正确写法（独占时原样移交所有权、共享时克隆并释放旧引用）相悖。 于是每写一次下标赋值引用计数就 +1，COW 守卫 refcount > 1 从此恒真： 每一次 a[i] = v 都深拷贝整个数组。
  • 后果：a[i] = v 循环 N 次即需 O(N²) 内存。实测 100 万次写需约 8 TB， 进程被 OOM Killed（sys 时间高达 3 秒）；同一程序修复后峰值约 10 MB、 耗时 0.01 秒。
  • 根因定位手段：在 dial_array_set 入口用 gdb 读 ((int64_t*)a)[-1]， 可见引用计数在 2 → 1 → 2 → 1 → 2 之间震荡（数组明明由槽位独占持有）。
  • 修复：dial_array_set 与 grow（push 路径）改为与 dial_map_put 完全同款的 所有权交接——独占时原样返回、不 retain 不 release；共享时克隆并 release 旧 buffer。
  • 附带修复：覆盖槽位时改为先 retain 新元素、再 release 旧元素。 原顺序在「旧元素 == 新元素」（如 a[0] = a[0]）时会把计数打到 0（free）， 紧接着又对已释放内存 retain —— use-after-free。
  • dial_array_clone 在独占数组上泄漏元素的引用计数：旧实现对「与原数组同一块 buffer 的别名」也调用 retain_elems，等于把同一批元素的引用计数凭空 +1， 而数组释放时只释放一次——元素引用计数净多 1，永久泄漏。 现 clone() 一律产出独立副本（先 retain 迫使深拷贝，再抵消该次 retain）。
  • 嵌套下标赋值 m[i][j] = v 的所有权结算错位：内层数组是从外层数组元素槽 借来的指针，其那一份引用属于外层数组；若内层 set 按「消耗引用」的语义 处理，会与外层的元素替换重复释放同一份引用。现新增 dial_array_set_borrowed （不消耗被借的引用，改为交出「一份新拥有」的引用），并在 codegen 中按 「消费者释放、变量槽转移」的规则结算。

  • dial_rc_clone 恢复纯粹语义：唯一持有者时原样返回、不再 +1； 多持有者时深拷贝。过去那个 +1 让 clone() 只能靠「别名 + 多一个计数」实现， 是元素引用计数泄漏与 COW 守卫误判的共同源头。 配套地，dial_string_clone / dial_bytes_clone 改为强制深拷贝产出独立副本 （否则纯语义下 b = s.clone() 会让 b 悬垂）。

  • 误拒合法程序 + 三处堆悬垂 + bytes[] 被拒 + 两处安全缺陷（本轮一并修复）：

  • ① select 分支里 move_to 外层变量被误报「已转移」：check_moved_stmt 的 Stmt::Select 分支既不做「只查 arm.chan」的纪律，反而又对 arm.body / default_body 递归了一遍 check_moved_stmt，与 check_stmt 的递归重复—— 同一条 move_to 被检查两次，第二次必然报「变量已转移」。现删掉分支内的递归， 只保留对 arm.chan 的 check_moved_expr（分支体仍由 check_stmt 递归各自检查， 恰好一次）。
  • ③ 结构体字面量 / 字段读取 / 字段赋值的堆字段未 retain：Expr::StructLit、 字段读取（t = p.name）、字段赋值（p.name = s）在写堆类型字段时只 store 不 retain，字段于是成了来源的别名；来源出作用域被 release 后字段即悬垂 （use-after-free，读到的长度字段可能是垃圾，打印出成片乱码）。现统一引入 retain_if_borrowed：借来的值（变量 / 字段 / 数组元素 / get·at）retain 一份， 自带所有权的值（字面量 / clone 等）直接接管。
  • ③ 的同族泄漏：a[i] = <字面量>、a.push(<字面量>)、a.set(i, <字面量>)、 数组字面量元素在循环里逐次泄漏一份引用（容器 retain 了元素，字面量自带的 那一份所有权却没移交）。现引入 settle_fresh_value：自带所有权的值在容器接管后 归还其临时所有权，借来的值则不释放——嵌套下标赋值 m[i][j] = v 也按同一规则结算。
  • ④ bytes[] 被 is_array_elem_type 拒绝：语义层漏收 Type::Bytes，但 codegen 的 array_elem_kind 早已把 Bytes 归为 kind=1（RC），两层不一致。现补上 Type::Bytes（dial_bytes_retain / release 内部即 dial_rc_*，完全兼容）。
  • ⑤ IR 验证失败不中止编译：module.verify() 失败只 eprintln 后继续 emit_object，可能产出无效 IR 或带未定义行为的机器码。现改为直接以易读文字 return Err(...) 中止。
  • ⑥ curl --proto '=https,http' 与「只允许 https」声明矛盾：https URL 可被 302 重定向到 http，中间人攻击窗口重新打开。现 --proto 仅放行 https（本机地址 经 http_allowed 判定才加 http），并新增 --proto-redir 限制重定向协议。

Added（新增）

  • 测试组 N：内存上界 + 所有权语义回归（tests/mem/）。
  • array_cow_bench.dial：100 万次下标赋值的基准，在 128 MB 虚拟内存上限下运行—— 一旦 COW 误判复发（需 TB 级内存）立刻被上限打爆。
  • array_cow_semantics.dial：逐条钉死 clone 独立 / COW 隔离 / 嵌套赋值 / 句柄元素数组四条所有权语义。
  • 测试组 O：所有权 / 语义回归（tests/sem/）：钉死「编译器应接受并正确运行」的合法 程序——select 里 move_to 外层变量（select_move_to）、StructLit / 字段读取 / 字段赋值的堆字段 retain（structlit_heap_field / field_and_assignfield）、 bytes[] 不被拒（bytes_array）、借来值写入容器不重复释放（borrowed_assign）。
  • 一键安装脚本彻底重写（tools/install-dial.sh / install-dial.ps1）：
  • 版本不再硬编码：优先从已装好的 dialc 读出真实版本号，bootstrap 才回退到内置 默认；配套件（标准库 / 插件）一律按该版本推导——消灭版本不同步。
  • VS Code 插件按 Release 资产清单解析真实文件名，不再依赖插件自身 semver 与 编译器版本号对齐（旧版写死 dial-0.98.1.vsix，每次都 404）。
  • 下载失败可见真实原因（旧版 2>/dev/null 把 curl 报错吞了）。
  • install-dial.sh 支持 bash / zsh / fish / profile 四种 shell 的 PATH 持久化，并提示 当前会话用法；新增 --help / --version / --uninstall，解压前校验压缩包完整性， 重跑幂等。

Changed（变更）

  • README §11.2 / §11.3：补齐「独占路径必须原样移交所有权、一个引用计数都不能动」 这条不变量（含做错的后果对照表），并把 clone() 的描述从「COW 感知克隆」 更正为「独立副本（深拷贝）」。
