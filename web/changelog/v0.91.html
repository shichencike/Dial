[v0.91] — 2026-10-30

本版落地多路复用 select（见 README §27.9）—— 同时监听多个通道，任一就绪即执行对应分支。

Added（新增）

  • 新语法（4 个关键字）： dial select { case recv(chA) as a { ... } case recv(chB) as b { ... } default { ... } } 刻意不照搬 Go：接收永远是函数调用 recv(ch)（没有 <- 运算符）， 绑定变量用 as 关键字（不是 :=）。select 是语句不是表达式—— 各 case 的绑定变量类型可以互不相同，不存在统一返回类型，编译期拒绝 let x = select {...}。
  • 内建语义三条： 1. case 只拿真实值：分支体内绝不会拿到空指针（底层非阻塞取，元素被抢走会自动重挑）； 2. 全体 EOF → select 直接结束：所有通道都「已关闭且已空」时，select 语句结束， 一个分支都不执行（包括 default）； 3. default 使 select 非阻塞：没有任何通道就绪时立刻执行 default，绝不等待。
  • 事件驱动的等待原语（C Runtime）：全局事件纪元 epoch + 全局条件变量广播。
  • 不丢唤醒：先读 epoch → 再查就绪 → 再睡到 epoch 变化，过期的等待假设永不成立；
  • 不死锁：notify 一律在释放通道本地锁之后调用， 「持通道锁 → 取全局锁」与「持全局锁 → 取通道锁」两种嵌套都不存在。
  • 随机选取就绪通道（防饿死）：多通道同时有数据时随机挑一个， 起点用原子递增计数器取模（不用 rand()——它不是线程安全的）。
  • C Runtime：dial_chan_epoch / dial_chan_wait / dial_channel_pick_ready， 以及 selector 对象（dial_sel_new / add / pick / recv / free）。

Added（测试与示例）

  • examples/select_two_channels.dial：双通道并发——两个生产者往不同通道发数据， 一个消费者同时监听；顺带校验「收到的确实是本通道的元素」（防串通道）。
  • examples/select_default.dial：default 的非阻塞语义。
  • examples/select_eof.dial：全体 EOF 时 select 直接结束。
  • examples/select_fairness.dial：随机选取的防饿死断言（两个通道都必须被处理过）。
  • 负向用例新增 9 个（case 非 channel / 元素类型未定 / 缺 as / 绑定变量作用域外使用 / case 不是 recv 调用 / select 为空 / 两个 default / select 当表达式 / case 用 try_recv）。

Fixed（修复）

  • IR 生成缺一条跳转导致编译器段错误：select 的 setup 块原先没有接上调用方当前块， 使 while 的 body 块变成无终结指令的空块，LLVM 在分支概率分析时段错误。 已补上「当前块 → setup」的跳转。

性能数据

场景 结果
50 万次 send + select（阻塞式，事件驱动） wall 0.19 s，CPU 0.36 s
同等工作量改用 default（非阻塞轮询） 空转 0.38 s 后卡死在 join（队列塞满、生产者永久阻塞），120 s 超时
8 消费者 / 100 万元素并发压测（F 组） 回归不变：received=1000000 duplicate=0

已知限制与未来方向

  • 惊群：全局广播会唤醒所有 select 等待者，多数醒来后发现「不是我」。 基线实现选择「逻辑正确 + 低延迟」优先于惊群开销（惊群只造成少量无谓唤醒， 轮询方案则持续 CPU 空转 + 毫秒级延迟）。 Linux 上可用 epoll + eventfd 消除惊群——v0.92 之后的优化方向，不影响本版语义。
  • select 不带超时：要「等一会儿再看」请用 recv_timeout 单独接收。
