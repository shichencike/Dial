[v0.81] — 2026-10-30 · 理由与证据链

本文件是 CHANGELOG.md 中 ## [v0.81] — 2026-10-30 版本段拆出的「理由 / 证据链」存档：为什么改、实测数据、边界在哪。 变更条目（新增 / 更改 / 破坏性变更 / 修复）本身仍留在 CHANGELOG.md。

本版补上 v0.8 并发模型唯一的功能缺口：通道的关闭与 EOF （见 README §27.7）。

缺口本身：v0.8 的通道没有 EOF。生产者一旦退出，消费者就永远卡在 recv 上—— 程序不是跑错，而是死锁。也就是说「生产者结束 → 消费者收尾」这个最常见的并发范式 在 v0.8 里根本写不出来。v0.81 让它可以写了。

修正的设计回退

  • v0.8 曾刻意不把 close 扩展到 channel，担心「关掉之后变量还在、作用域结束再 release 一次」造成二次释放。复核后确认该担心不成立：close 只置标志 + 广播， 既不释放通道对象也不动引用计数；对象销毁仍只由原子 ARC 归零触发一次。二者职责不重叠。

测试

  • A 组新增 examples/channel_close.dial（生产者 close → 消费者 done 收尾）与 examples/channel_try_recv.dial（len / try_recv / closed / done 状态机）， 各连跑 10 次输出逐字节一致。
  • B 组新增 11 个负向用例（错用 close / closed / done / len / try_recv、 元素类型未定就 try_recv、用保留名定义函数与结构体）。
  • D 组新增 tests/trap/channel_send_after_close.dial：关闭后 send 必须信号终止且不打印哨兵； E 组 --fast 下恢复 UB（打印哨兵），证明陷阱确由编译器插入。
  • 压力测试：20 万次移交 + EOF 收尾，RSS 稳定 1.4 MB 不增长，无死锁、无泄漏。
