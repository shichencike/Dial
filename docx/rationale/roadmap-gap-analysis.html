缺口盘点与执行路线图（2026-11-18，源码核实版）

本文是「代替 LLVM」主线下对当前缺口的系统盘点，以及据此制定的分梯队执行计划。 与以往凭印象的盘点不同，每一项都经过源码核实：区分「LLVM 有而 asm 无」（可在 LLVM 零改动护栏内补）、「两后端共同缺的语言特性」（加它须改 codegen.rs/semantic.rs， 违反护栏）、「战略/宪法否决」（永久不做）、「过时文档」（不是缺口）四类。

0. 护栏（路线的硬边界）

  1. LLVM 路径零改动：src/codegen.rs、src/ast.rs 相对基线冻结。
  2. 语义构造已清零（M7-e3as 后，LLVM 能编译而 asm 拒绝的构造为零）。
  3. AArch64 普通程序零变化；版本 1.10.0；零新依赖；docx 确定性；不打 tag。
  4. 每批带 A/B 交替 + 归因 + 全门禁 + 证据链。

推论：只有「LLVM 已支持、asm 缺失」的项能在护栏内补齐；语言层新特性若要动 codegen.rs，必须先申请放宽护栏或列为独立版本主题，不能塞进 asm 后端批次。

1. 盘点结果（四类）

A 类 · LLVM 有而 asm 无 —— 护栏内可做

盘点结论：此类已清零。逐一核实：

候选 LLVM 状态 asm 状态 结论
内联汇编 @asm/@asm_intel 支持 M7-e3as 已支持 已清零
impl 具名类型方法（self） 支持 M7-e3aq 已支持 已清零
嵌套下标赋值 a[i][j]=v 支持 e3ao 已支持 已清零
sizeof/alignof/offsetof、bitcast、assert/panic、is_null、drop、channel、spawn/join、HOF、select 支持 e3ag~e3an3 全支持 已清零
SIMD simd<T,N> 支持 战略拒绝 M7-e3x 定量否决（−6.7%），不算缺口

B 类 · 两后端共同缺的语言特性 —— 须改 codegen.rs，违反护栏

这四项经源码核实 LLVM 后端也没有实现，加它们必须改冻结文件：

项 核实证据 性质
select 语句级超时 src/codegen.rs 无 select timeout 实现；README:2116 记「未实现」，变通为单通道 recv_timeout 语言新特性，两后端共同缺
impl 关联函数 T::new()（无 self） gen_method_call 与 make_impl_call 均假设 self=params[0]；semantic.rs:354 明确 self 是首参；无无-self 分派 语言新特性，两后端共同缺
map<K,string> 值 / values() 非 int semantic.rs:3952 语义层统一拒绝 语言新特性，两后端共同缺
线程池 / 协程 / 异步、原子类型 / 无锁结构 README:2118-2119「未实现」 触及内存模型与并发宪法，需设计裁决

结论：这些不是 asm 后端落后 LLVM，而是语言本身尚未提供的能力。在「代替 LLVM」 语境下它们不构成差距（LLVM 也没有）；要做必须作为独立语言版本主题并改 codegen.rs， 不属于 asm 后端补齐范畴。

C 类 · 性能层 O3 —— 真正的剩余工程，但高成本/边际

项 现状 决策
caller-saved GRA 未做 M7-e3at 量化否决（上界比 0.629<1、86.8% 栈槽仅访问≤2 次为 ABI 强制落栈），附重启条件
浮点 / 跨函数寄存器分配 未做 高成本内核级方向，建议先做同类收益诊断再决定（延续 e3at 纪律）
多级管线（LTO 级） 未做 同上，须先量化
ISA 微融合 POPCNT/LEA/掩码/常量乘已做 e3au 后边际收益递减，b02/b13/b22 落后项是 C runtime + idiv 微码主导，非微融合可解

基准现状（几何平均 ~0.54x，整体领先 LLVM ~46%；胜/平/负约 14/10/4）： 算术类基本持平（0.985x）、数组类领先（0.76x）、递归类大幅领先（0.025x）、 位与控制流领先（0.81x）、字符串类略落后（1.09x）。

D 类 · 战略/宪法否决（永久不做，不进计划）

SIMD 完整后端（−6.7%）、caller-saved GRA（ROI 为负）、函数名重载、闭包、 运算符重载、用户自定义泛型/接口/trait、可变全局状态、追踪式 GC。

E 类 · 过时文档 / 不是缺口（核实后排除）

  • README:590「DWARF 尚未开工」是 e3v 段落的历史叙述，紧接 e3w 已落地（37 处 DWARF 代码）。
  • README:338「尚未覆盖嵌套下标赋值」在 e3as 批次已修正。
  • lower.rs:1602 TypeLit 独立表达式：LLVM:4211 同样拒绝（「应由 Sema 先行拦截」），两后端同源。
  • builtin.rs 的 thread 构造 / 布局内建「后续相位」：thread 构造 LLVM 自身未单独实现； 布局内建已由 e3e 落地，属过时注释。

2. 执行路线图（按护栏兼容性与 ROI 排序）

阶段一：护栏内的确定性工作（低风险）

  1. 过时文档清理：修正 README:590 等历史叙述的时态标注，避免误导（纯文档）。
  2. 收益诊断工具化：把 e3at 的 tools/diag_gra.py 思路扩展到浮点/跨函数 GRA， 先在 bench 与真实 workload 上量化 ROI（纯工具，零产品代码改动）。

阶段二：C 类性能方向（先诊断后投入）

  1. 浮点寄存器分配收益诊断 → 若 ROI 为正再实现。 ✅ 已完成（M7-e3av）：诊断为正收益缺口（浮点全 spill，静态栈访问比 5.8×、 动态 asm/LLVM 3.0×），已实现 fGRA（浮点寄存器驻留），动态比降至 1.64×。 剩余边界（含 call 函数 / 单块函数）受 SysV xmm 全 caller-saved 结构性限制、 且 bench 无含 call 浮点函数（浮点栈访问合计 0），ROI 为负，不再投入。
  2. 跨函数寄存器分配收益诊断 → 同上。 ⏸ 实质已被覆盖：整数 caller-saved 由 M7-e3at 量化否决（上界比 0.629<1）； 浮点跨 call 因 SysV xmm 全 caller-saved（无 callee-saved 兜底）结构上不可行， 比整数更差。无新 workload 触发则维持否决（见 e3at 重启条件）。
  3. 字符串类落后项归因：b20/b22 的 C runtime 开销是否有 asm 侧可优化空间 （如 substring 的边界检查、拼接的拷贝次数），先归因后动手。 ✅ 已完成（M7-e3aw 附带）：字符串类已追平 LLVM（几何平均 1.0016x，优于 原记录的 1.02x；b20 0.949x / b21 0.984x / b22 1.107x）。唯一落后项 b22 的 反汇编确认瓶颈是 dial_string_substring 库调用（每次分配新字符串）+ s % 1e9+7 魔数除法（数据依赖、无法强度削减）；LLVM 靠 O3 把 28 个基准内联进 main 并用 循环管线优化——架构级差距，peephole 不可达（与 e3r/e3s/e3t 结论一致）， 无 asm 侧可落地空间，不改动产品代码。

阶段二补充：编译速度维度（M7-e3aw）

  1. ✅ 前端常量折叠解释器记忆化：插桩归因发现 e3p 的 fold_pure_calls 占 asm 前端近半（34.5ms），根因是朴素递归解释器对 fibR(23) 等纯递归函数重复求解 97 万步。加 (name, args)→result 记忆化后编译提速 ~30%（bench 112.9→76.1ms）， 折叠值与生成 .s 逐字节不变。这是「代替 LLVM」在编译速度维度上首个前端 算法级改进（e3an3 是产物/链接层）。

阶段三：B 类语言特性（需单独裁决，默认不进 asm 批次）

  1. select 超时 / impl 关联函数 / map string 值 —— 若要做，作为独立语言版本主题， 明确放宽 codegen.rs 零改动护栏，双后端同步实现 + 全门禁。
  2. 线程池 / 协程 / 原子 —— 先做内存模型宪法裁决（数据竞争、§20 零悬垂底线）， 裁决通过才进入设计。

3. 一句话结论

语义层 asm 已完全追平 LLVM；剩余差距全是性能深度与语言层新特性。 前者须用收益诊断决定投入（高成本、易负收益），后者须改冻结文件、超出 asm 后端补齐范畴。 护栏内真正低风险可做的，是收益诊断工具与过时文档清理；其余要么先量化、要么先裁决。
