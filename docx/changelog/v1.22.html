[v1.22] — 2026-11-25

Added（M16 asm 后端动态链接库 --shared）

  • --shared 产物形态（dialc build foo.dial --shared -o libfoo.so）：自研 asm 后端首次可产出 ELF 共享对象 / macOS dylib / MinGW dll，供 dlopen/dlsym 与 链接器 -l 使用。只有 export fn 成为导出符号（私有 fn 不导出）。与 --single-file / --tiny Fail-Fast 互斥；可与 -O0..3 叠加。
  • C 运行时 PIC 重编：--shared 绕过非 PIC 的预编译 libdial_std.a，强制 C 源码加 -fPIC 重编并存到独立缓存分区（key 含 -fPIC）。根因：默认归档有 2714 处 R_X86_64_32S 绝对重定位，dlopen 到任意基址后 ARC 元数据错位 → 实测含字符串拼接的导出函数 double free；PIC 重编后无 TEXTREL、500/1000 次 ARC 调用稳定。
  • dlopen 自动初始化：链接期注入带 .init_array constructor 的小对象，库加载 时自动调 dial_env_init(0, 0)。否则 g_rng_state=0 使 xorshift 退化、random() 恒返回 0（实测）。constructor 用 0 参数：种子由 time(NULL) 参与保证非零，argv 快照为空（库本无 argv）。
  • 输出提示文案区分「动态链接库」/「可执行文件」；usage 增补 --shared。
  • R35 门禁：ELF 共享对象类型 + 导出符号 + 无 TEXTREL + dlopen 调用（含 1000 次 ARC 循环 + random 非退化）+ 冲突矩阵；默认可执行路径零回归。

Added（M11~M15 对齐 C 工具链 O2/O3 优化）

  • M11 通用函数内联（pass::inline_calls，O2+ x86-64）：对标 gcc/clang -O2 inlining。Private 小函数（≤96 指令 / ≤16 块 / 非递归）体复制到调用点，vreg 与 block id 全量重映射、入口补回写参 Store（补 codegen prologue 的隐式写参）、 ARC retain/release 原样保留、Return 改 φ 回传到 continuation。不动点 3 轮。 排除 -g/PGO/插桩（DWARF 行号与 profile idx 对齐）；Line/DebugVar 不复制。
  • M12 通用 LICM（pass::licm，O2+ x86-64）：循环不变纯计算外提到 preheader。 标准自然循环识别（入口块被卷入则整块跳过）、只外提定义块 ≥ preheader 的指令 （保证向前搬）、Load 仅在 ptr 槽循环内未被 Store/ARC 归零/取别名/调用逃逸时 外提、Div/Mod 不外提（trap 位置）、不动点 8 轮 + DCE。
  • M13 保守 SCCP（pass::sccp，O2+ x86-64）：格 Option<Imm> 沿 CFG/块参数 φ 不动点传播，只信任立即数与纯整数/比较/转换折叠结果；把 cond 为整数常量的 Branch 改为 Jump，不删除任何块/Call/Store/ARC（零副作用变更）。
  • M14 死函数消除（pass::eliminate_dead_functions，O1+ x86-64）：Private 且 全程序零引用（Call/FuncAddr 均计引用）的函数不动点删除；main / 导出 / 函数指针 引用保留。
  • M15 保守循环展开（pass::unroll_loops，O3 x86-64）：精确匹配标准 for 5 块 骨架（上界常量 2..8、iv 0 步长 1、无 φ、body 仅纯整数栈指令），复制 N 份 body+latch 串成链、末份跳 exit。运行时上界 / 上界过大 / 含副作用一律放弃。
  • 调试设施：DIALC_DUMP_LICM / DIALC_DUMP_SCCP / DIALC_DUMP_UNROLL 打印各 pass 生效计数。
  • 门禁 R30~R34：O0/O1/O2/O3 逐字一致 + asm/LLVM 双后端逐字一致 + 各 pass 生效 证据 + 反例零误拒；GRA 驻留 / x86 移位形态门禁改用 export fn 测试目标以适配 内联+死函数消除（非真实回归）。全量回归零回归、单测 41 项、CVE 8/8。

Added（M10 字符串拼接常量折叠：对齐 gcc -O2）

  • L1 字面量拼接折叠（pass::fold_string_concat，O1+）：编译期把静态串之间的 dial_string_concat 合并成单个静态对象，不动点迭代支持 "a"+"b"+"c" 链式； 内容逐字节等价、静态串 immortal 故 ARC no-op、AArch64 亦安全。
  • L2 累加循环折叠（pass::fold_string_accum，O2+ x86-64）：严格识别 x=S0; for i in 0..N { x=x+C } 且退出块仅用 length/get + 纯算术的骨架， 符号执行算出 final=S0+C·N 与 return 常量，把整函数折叠成单块 return const （对标 gcc -O2 对 bench.b20 的折叠：b20 从含 4000 次堆拼接变成一条 mov $124272）。 零误拒护栏：前缀追加 / 循环体副作用 / 非静态追加串 / iv 退出块再用 / 超长串 一律放弃；采样经 R29 门禁 + 全量 1112 项回归验证。
  • 调试设施：DIALC_DUMP_ASM_IR / DIALC_DUMP_ASM_IR_POST 环境变量打印优化前/后 IR。
  • 说明：LLVM 后端从 AST 直接生成、不经此 pass，但输出与折叠后的 asm 逐字一致 （折叠是等价变换）；bench/bench.dial 的 b20 校验和 124272 与 O0 完全相同。

Added（零标注借用检查器 + 门禁盲区修复）

  • 借用检查器（NLL、零生命周期标注）：语义分析阶段新增纯分析 pass，基于内部数据流 计算借用区域，检测「借用指针（s.as_c_str() / b.as_ptr()）仍在使用、来源却被 move_to / drop / 重赋值 / spawn / own 接管」的悬垂 use-after-free，编译期 Fail-Fast，错误码 dialc.borrow.dangling。NLL：借用到指针最后一次使用为止，此后 释放来源合法；&x 栈值借用不检查（零误拒）。用户无需写 'a 等任何生命周期标注。 纯分析不改 IR / codegen，双后端天然一致。见 README §31.7、R28 门禁。
  • 本地门禁补齐 cve_check：v1.21 发布事故（cve_check 只在 CI 跑、本地全绿却 tag CI 失败）的流程盲区修复——tests/run_tests.sh 按 CI 同口径纳入 CVE 暴力检测 AP3 段。

Fixed（结构化错误码 CLI 贯通）

  • 缺陷 #5 修复：此前 frontend 把 DialcError 降级成 String，CLI 只能从消息文本 反解错误码，措辞一改工具就废。现 frontend 返回结构化 FrontendError（保留 code）， diagnostic::report_with_code 优先用结构化码；CLI 人读 / JSON 与 LSP 三处对同一错误 显示一致的 dialc.borrow.dangling 等码。

验证：全量回归 1112 项通过（原 1099 + 新增），R28 门禁 2 项全绿，CVE 8/8，零误拒。

性能基准（v1.22 发布前同机实测刷新）

本版发布前用现有四语言套件重跑全部 28 项微基准（bench/data.json 快照， docx/bench.html 同步重生成，check_bench_data 全绿）；统一外部墙钟、校准重复数、 扣 noop 基线、112 项校验和逐项一致。工具链：gcc 13.3 -O2 / Go 1.21.4 / CPython 3.11 / dialc 1.22.0 --fast。

  • 速度几何平均（C=1.00×，越小越快）：C 1.0000× / Dial 1.0244× / Go 1.4967× / Python 34.44×。Dial 与 gcc -O2 基本持平，明显快于 Go。 28 项纯计算耗时之和：C 42.49ms / Dial 48.51ms / Go 50.60ms。
  • Dial 最快 5 项：b01 整数累加、b09 二叉递归 fib、b10 浅递归、b11 递归树、 b20 字符串循环拼接（M10 折叠生效，对标 gcc -O2）。
  • 六维工程指标：Dial 启动 0.532ms（四语言最快）、b17 峰值 RSS 1444KB（最低）、 产物 183.83KB（Go 1941.72KB）；Go 编译最快 69.5ms，Python 编译/体积占优。
  • 已知短板：b17 矩阵乘 7.01×、b12 互递归 3.71×、b23 popcount 3.32×（asm 后端未做向量化/更激进的循环优化），列为后续方向，不影响本版功能交付。
