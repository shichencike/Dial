  • M7 性能批次（寄存器分配前的指令密度攻坚）：
  • M7-a1 算术源操作数折叠：x86-64 的二元/比较指令允许一个内存操作数， 原先每条 Bin / ICmp / FBin / FCmp 都要 lg(b, g2) 把第二个操作数搬进 %r10 / %xmm9；现在直接发 addq off_b(%rsp), %rax 这类形式， bench.dial 静态指令数 4971 → 4772（−199 / −4.0%）。立即数仅在 imm32 范围内且指令支持 reg, imm 形式时折叠（imul / idiv / 移位 / 浮点不折叠）， F32 槽只写低 4 字节故不折叠以免读入垃圾高位；AArch64 是 load/store 架构， 保持原路径不变。双后端黄金门禁（10 正向 + 2 负例 + AArch64 交叉汇编）与 全量测试全绿。此步只减搬运、不触及栈帧布局，是 M7-a2 寄存器驻留的前置。 --quick（2 采样）读数为 1.4032x，落在基线 1.3575x 的噪声区间内， 不作为性能结论；确定性指标是静态指令数。
  • M7-a2/a3 块内寄存器驻留 + 局部变量槽提升（本批次主体）：
    • 瓶颈定性：全 spill 版的热值其实在 Alloca 局部变量区，不在 vreg 槽。 b23 内层循环 24 条指令里每次迭代都要反复 Load/Store 同一批栈地址； 只把 vreg 驻留进寄存器（a2 单做）反而因块头装载 / 块尾回写让静态指令 4772 → 5109、性能不升反降。必须把局部变量槽本身提升进寄存器池。
    • 寄存器池 8 个：6 个 SysV callee-saved（rbx/rbp/r12–r15，prologue 用帧内 mov 保存、epilogue 恢复，不动 rsp 以免所有 off(%rsp) 偏移失效）+ 2 个 caller-saved（r8/r9，因启用驻留的块内一条 call 都没有而无需保存）。 刻意避开 rax/rcx/rdx/r10/r11（临时寄存器与 div / 移位 / setcc 隐式操作数）。
    • 安全护栏：含 Call / CallIndirect / ARC / EnvInit 的块一律禁用驻留—— longjmp 会把 callee-saved 恢复到 setjmp 时刻的值，「寄存器比栈新」的前提 在那条路径上不成立；纯计算块不受影响。指令数 < 6 的短块也不启用， 避免装载/回写开销超过收益（递归函数体的净退化就是这样消掉的）。
    • 逃逸分析：只有地址完全不逃逸（不被当作值传给任何指令 / 块参数 / 返回值， 不经 FieldAddr / PtrAdd / ARC 间接访问）、且所有 Load/Store 都是 8 字节整数 宽度的 Alloca 才提升；窄整型走 movzbq/movl 零扩展、浮点走 xmm，语义不同， 一律不提升。
    • 活跃性回写：块尾只回写 ① 提升槽（别的块/含 call 块仍走内存）② 跨块 仍被读取的普通 vreg；块内临时值写完即弃。term 仍在驻留态发射，phi 实参 / 返回值直接从物理寄存器读，但 sv 强制写目标块 param 的栈槽，保证后继块 不会读到旧值。
    • AArch64 保持原全 spill 路径不变（save_bytes = 0、plans 全空）， 交叉汇编门禁通过。
  • 量化结果（--quick，2 采样；校验和 28×2 全一致，双后端黄金门禁 10 正向
    • 2 负例 + 全量测试全绿）：几何平均 1.3575x → 1.2676x，逐项胜/平/负 3/2/23 → 5/4/19；b23 popcount 4.758x → 2.508x，b25 三路分支 1.103x → 0.865x（反超）、b26 0.656x → 0.598x、b05/b07 由负转正。静态指令数 4971 → 4885。--quick 单次读数有噪声，但 b23 的降幅与静态指令数下降 是确定性的，结论可靠。
  • M7-b 全函数统一寄存器文件（跨块零 spill）：
    • 触发条件：整个函数所有基本块都不含 Call / ARC / EnvInit（纯计算函数）。 这类函数内没有任何调用会破坏物理寄存器，池寄存器由 8 扩到 10： rbx/rbp/r12–r15/r8/r9 之外把 rsi/rdi 也纳入（prologue 读完 C ABI 参数后 即空闲；逐块模式仍只用前 8 个，避免与 inst_call 的传参互相踩踏）。 含 call 的函数继续走 M7-a 的逐块独立驻留。
    • 统一绑定：全函数选出一至多 10 个位置固定绑定物理寄存器，所有块的 resident 完全一致——任意两块之间都是「兼容边」，值天然留在寄存器里， 块尾零回写、块头零装载。热点循环（如 popcount 的 while 体）从此不再有 「flush 提升槽回内存 → 下一轮 load 回来」的固定往返。
    • 循环嵌套深度加权：若按静态指令数平权选 top-N，最内层循环（动态执行 数十万次）的中间值会被入口 / 出口块的冷值挤出寄存器，反而退化成栈槽往返 （首次实测几何平均一度从 1.2738x 恶化到 1.3068x）。现按回边区间计算每块 嵌套深度，权重 深度 0/1/2 → 1/8/64，让 top-N 优先覆盖最内层循环。
    • 正确性护栏：函数入口把参数提升槽从 Alloca 区一次性装载到 p；phi 参数 因 write_block_args 写入目标块 param 的栈槽，强制从同一槽装载；p 是提升槽 的唯一权威，内存 Alloca 区只在入口作参数来源、全程不回写（函数内无 call， 不存在需要「内存权威」的边界）。AArch64 保持全 spill 路径不变。
    • 量化结果（--quick，2 采样，两次取数；校验和 28×2 全一致，双后端黄金 门禁 10 正向 + 2 负例 + AArch64 交叉汇编 + 全量测试全绿）：几何平均 1.2738x → 1.247x–1.251x，b23 popcount 2.508x → 约 2.0x、 b05 连乘幂 1.216x → 0.898x（反超）、b07 迭代斐波那契 0.951x → 0.915x。 逐项胜/平/负在 5/4/19 附近波动（2 采样的胜负边界噪声较大），确定性结论 是 b23 降幅与静态指令数 4885 → 4775：b23 内层循环实现零栈往返 （14 条全为寄存器指令，含 sarq %cl, %rsi）。
    • 剩余差距：递归调用类几何平均仍约 1.78x（含 call，享受不到统一文件， 还要承担 prologue/epilogue 保存）、b08 3n+1 2.78x、b23 约 2.0x、数组 / 字符串类 1.15–1.28x。下一步 M7-c：指令选择与拷贝合并——b23 内层 14 条 里仍有约一半是 movq 寄存器搬运（SSA 临时值各自绑不同 p），让 def 复用 首个操作数的物理寄存器（coalescing）可再砍掉一半；以及含 call 函数的 跨块协调（递归类反超的主战场）。
