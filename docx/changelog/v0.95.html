[v0.95] — 2026-10-31

本版是 dialc lsp 的第一次增强（见 README §28.6）： 把 v0.94 骨架里「刻意没做」的三件符号表能力——悬停（Hover）/ 跳转定义（Go to Definition）/ 基础补全（Completion） ——一次性补齐。底层是一座与类型检查解耦、可容错的跨文件符号表（src/index.rs）， 它复用 parse_diali / resolve_type_name，但不调用 semantic::analyze， 所以半句没写完的代码也照样能索引、照样能给 Hover 与补全。

Added（新增）

  • GitHub Actions 流水线 .github/workflows/ci.yml（编译 + 发布流程）：
  • build 作业（每次 push / PR）：装 LLVM 18 + Rust → cargo build --release --locked → 跑全部十一组端到端测试（A～K）→ 校验内部锚点 → 校验 docx/ 与文档同步； 四道关卡任何一道不过，PR 即不可合并。
  • release 作业（打 v* 标签时）：复用 build 的二进制， 打成 dialc-v<版本>.zip（源码 + .git + 四份许可文件 + docx/ + VS Code 扩展 + bin/dialc）， 上传为 GitHub Release 产物——即官网首页的下载链接。
  • 环境与 README §3.1 一致：Ubuntu 24.04 LTS（近两年内发布的发行版）、Linux x86_64 · 动态 glibc。
  • 新增模块 src/index.rs：作用域树（Scope，parent 链）+ 符号表（Symbol），独立于类型检查。
  • 作用域链「由内向外」查找，与 semantic::lookup_type 语义一致，因此 if 块里 let x: int 遮蔽外层 let x: string 在 Hover / 定义 / 补全三处都查的是内层那个 x。
  • 跨文件符号：通过 import 自动扫描 ~/.dial/packages/<name>/，复用现有 find_installed / verify_iface / parse_diali 拿到包的导出（不透明类型 + extern fn）， 并记下来自 .diali 的声明行号与 /// 文档——这两样是「跳进 .diali」与「Hover 显示包文档」的素材。
  • Hover（textDocument/hover）：
  • 文件内符号（函数 / 结构体 / 局部变量 / 形参）显示名称、推断类型与声明处片段；
  • 包符号显示函数签名 + .diali 里的 /// 文档，并标注 「外部函数」。
  • 跳转定义（textDocument/definition）：
  • 文件内符号 → 返回本文件的精确 Location（UTF-16 列换算，精确到标识符起止）；
  • 包符号 → 返回 .diali 文件的 Location，落点正是该 extern fn 的声明行。
  • 基础补全（textDocument/completion，触发字符 .）：
  • 收集光标可见作用域内的全部符号（本文件局部 + 全局函数/结构体 + 已 import 的包符号）；
  • 按光标处已输入前缀过滤（demo_ 前缀只留 demo_add，不会把 total / DemoHandle 混进来）；
  • 即使光标落在空白（前缀为空）也返回当前可见的全部候选。
  • AST / 解析器 / 包接口补上位置字段（稀疏、小改）：VarDecl / For / Catch / SelectArm 的变量名位置， Func 的名字与每个形参位置，StructDef 的名字位置；.diali 的 type X; 与 extern fn f 也记下声明行号。

Changed（变更）

  • initialize 能力协商新增 hoverProvider: true / definitionProvider: true / completionProvider: { triggerCharacters: ["."] }（v0.94 仅有语义高亮与诊断）。
  • didOpen / didChange / didSave 在发诊断之外，额外把文件喂给符号表索引； didClose 时从工作区索引里移除该文件，避免残留。

Added（测试）

  • 测试组 K（tests/lsp_features.py）：真起 dialc lsp 子进程按 LSP 协议往返，覆盖： 1. Hover 区分同名变量遮蔽（内层 x: int ≠ 外层 x: string）； 2. Hover 包函数的 .diali /// 文档与「外部函数」标注（跨文件符号）； 3. 跳转定义对文件内符号回本文件、对包符号跳进 .diali； 4. 补全收集可见符号 + 前缀过滤（含空白光标全量）。

刻意未做（与 v0.94 规划一致，本版仍不做）

  • 重命名（rename） 与 跨文件引用查找：需要全工作区重索引 + 引用图，当前索引器只建符号、不建引用边。
  • 格式化：Dial 没有官定代码风格，格式化交给编辑器/用户。
  • 诊断下放到 didChange：打字到一半的代码必然有错，边打边报只会让红线在半句话上闪；诊断仍留给保存时。
  • LSP 框架（tower-lsp 等）：本服务仍是手写的「读 JSON / 写 JSON」，框架的异步运行时与依赖树不划算。

Docs（文档）

本版一并修掉此前遗留的文档自相矛盾（均为「文档说的」与「实际做的」对不上，读者会被误导）：

  • 标题版本号与内容对不上：README 首行标题与官网 spec.html 的 <h1> 仍写 v0.94， 而正文已含 §28.6（v0.95）。现已统一为 v0.95，§17.2 标题「截至 v0.94」同步改为「截至 v0.95」， 并修正了三处指向 §17.2 的失效锚点（原先分别写作 v091 / v092，与标题都对不上）。
  • import / .dialpkg 的版本号写错：§25 状态、§25.9 标题、§17.2 表格均写 v0.92， 但 CHANGELOG 里 v0.92 是 char 类型、import / .dialpkg 是 v0.93 才落地。三处已改为 v0.93。
  • .diali 的 type / extern fn / /// 在语言层没有定义：§4.3 关键字表与 §9 函数定义里都没有它们， 而 §25.2 却在用这套语法写示例。现已在 §25.2 明确标注这是包分发层的接口文件专用语法，不属于 Dial 语言， 并在 §4.1（/// 仅存在于 .diali）、§4.3、§9.1 三处各加一句交叉指引。
  • §22「版本变更摘要」名不副实：内容停在 v0.3（v0.4~v0.95 一条没有），已改名为 「早期版本摘要（v0.3 及以前）」并指向 CHANGELOG（v0.4 及之后的完整记录在那里）。
  • §12.3 交叉引用错误：写「见 §13.5」，但 §13 没有 13.5（实为 §14.5）。链接锚点本就指向 14.5， 只有显示文字写错，已改正。
  • 测试组顺序混乱：长期是 A/B/D/E/C/F/G/H/I/J——C（产物契约）夹在 E 与 F 之间，既非字母序也非逻辑序。 现已统一为 A→K（C 移到 B 之后），tests/run_tests.sh 的执行顺序与 README §18 的表格同步调整； 并修正了脚本里「I 组是 v0.93 新增」的错误标注（实为 v0.94）。
  • P2 遗留项补齐：① §19.2 补上 ARC 不解决循环引用的讨论（泄漏 vs 悬垂的取舍，及四条处置办法）； ② §17.2 的 select 超时行改写，明确「未实现的是 select 语句级超时，recv_timeout 早已实现」， 消除误读；③ §24.4 的文件 IO 示例补上 try（§24.2 规定 open/read/write 失败即抛 Error， 原示例不包 try 属于错误示范）；④ §27.10 补上 --fast 下 select 的行为—— 三档安全等级完全一致（协议语义），唯一随等级变化的是「向已关闭通道 send」的 Fail-Fast 断言。
  • §28.4 表格时空错乱：该节标题是「v0.94 刻意没做的部分」，表格首行却写「已在 v0.95 落地」。 已在节首加说明：本节记录的是 v0.94 当时的决策，前三项已在 v0.95 推翻（并链接 §28.6）。
  • 锚点体系统一（顺带修掉一批「点不动的链接」）：README.md 的手写锚点一直是按 GitHub 的规则写的， 而官网生成器 tools/build_web.py 的 dial_slugify 与之不一致（多保留反引号、把连续空格折叠成一个连字符）， 于是同一份链接「在 GitHub 上能跳、在官网上跳不动」。 现已让 dial_slugify 严格复刻 GitHub（github-slugger）语义，两者同源； 并新增 tools/check_links.py 做锚点一致性校验（可 --fix 自动修正）。 实测：README 的 6 处失效锚点、CHANGELOG 的 25 处失效锚点全部归零， 生成后的 docx/spec.html（232 条内部链接）与 docx/changelog.html（77 条）零失效。 另修掉 CHANGELOG 里 25 处 ](#…) 跨文件链接——它们在 CHANGELOG 内部根本解析不到， 已改写为 ](README.md#…)（链接文字里的 §20→§21、§22 旧标题等一并更正）。
