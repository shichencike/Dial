[v1.21] — 2026-11-24

本版是「预处理设施大补齐」的交付版本：字段级 ARC、调试期裁剪、专门的预处理阶段、 条件编译 @cfg 与 AST 宏、# 文本级预处理指令五批改动合并发布。按 README §23 的「小功能 / 新语法 +0.01」标准，从 v1.20 递增到 v1.21（不按大版本 +0.1 跳档）；发布标签 v1.21，资产名按版本号推导（dialc-v1.21-*.zip / dial-1.21.0.vsix）。端到端全量回归 1099 项全绿、单测 41 项全绿。

Added（# 预处理指令：文本级预处理层）

  • 新增独立模块 src/directives.rs：编译流水线最前端、词法之前的文本级预处理层， 与 §39 的 @cfg / macro（词法后的 AST 级 pass）并存互补、职责不重叠。首批三类指令：
  • 宏 #define / #undef：对象式（token 级替换，不误伤字符串字面量内部）与函数式 （形参替换 + 嵌套调用）。函数式须 NAME( 紧邻；自引用按 C 语义不再展开，深度上限 64 防间接递归。命令行 -D NAME / -D NAME=value（别名 --define，可重复）注入初始宏表。
  • 条件编译 #if / #ifdef / #ifndef / #elif / #else / #endif：支持 defined()、 C 运算符优先级、整数（0x/0b/0o + _）、字符串/字符字面量；未定义标识符为 0。 假分支整块裁剪（含其中的 #error / 未知指令），裁掉的行以空行占位保持行号，诊断不漂移。
  • 诊断 #error / #pragma：活跃分支 #error 立即 Fail-Fast（带路径行号）； #pragma once 由模块去重天然满足、接受为空操作，未知 pragma 记日志忽略。
  • Fail-Fast：未闭合 #if、孤立 #endif/#else/#elif、重复 #else、#define 缺名/非法形参、 宏重定义内容不同、宏实参个数不符、#if 表达式错误/除零、未知指令——一律当场报错。
  • 挂接点：preprocess::collect_sources 中 lex 前跑文本 pass、lex 后做 token 宏展开（在 import_specs 之前，使 -D/#define 能改写 import 字符串）；PreprocessOptions 加 defines 字段；main 加 -D/--define 解析与 mod directives。
  • 验证：单测 40 项全绿（新增 16 项覆盖对象式/函数式/嵌套条件/defined/undef/-D/Fail-Fast 等）； R27 门禁 4 组（双后端逐字一致 + -D 注入 + 五类 Fail-Fast + 假分支忽略），双后端一致。 文档见 README §41。

Added（条件编译 @cfg 与 AST 宏）

  • 条件编译 @cfg(cond)：复用 @ 注解前缀（零新增词法关键字），可作用于顶层 fn / struct 与语句/块。条件语法：裸名布尔（debug / my_flag）、键值 （target_os = "linux" / feature = "x"）、!cond、all(...) / any(...)。
  • 内置维度：debug（随构建模式）、target_os / target_arch（宿主 triple， 遵循 DIAL_TARGET 覆盖）；自定义维度来自 CLI --cfg key[=value]（可重复， 无 = 视为布尔真）。
  • 在预处理阶段求值：假则整块/整项删除（不参与类型检查），真则清除标记； release 产物零被裁剪分支的字符串/符号残留；调用被裁剪的函数如期报未定义（Fail-Fast）。
  • AST 宏 macro name($a, ...) { ... } + name(args)：普通调用语法，预处理阶段做 AST 展开（非文本替换）。$a 词法为 Ident("$a")，展开时按 $ 前缀把实参表达式 替换进宏体的所有语句上下文（含嵌套表达式、子块）。支持宏体调用其它宏（递归展开， 深度上限 64 防自递归），宏名遮蔽同名函数，参数个数不符/重名宏当场 Fail-Fast。
  • 两端共用同一份展开后的 AST，dialc test / LSP 亦看到展开结果。
  • 实现落点：lexer（$name → Ident）、ast（CfgCond / MacroDef + cfg/macros 字段）、 parser（注解/宏定义解析，均为上下文关键字不新增保留字）、preprocess（eval_cfg / cfg_program + 宏展开两道 pass，位于 debug 裁剪之前）、main（--cfg 解析与透传）。
  • 验证：R26 门禁 7 项全绿（cfg 各维度 + --cfg + release 零残留 + 宏参数/嵌套/ 遮蔽 + 递归宏 Fail-Fast + 孤立 @cfg Fail-Fast + cfg 假分支跳过检查 + 宏体 cfg 求值， 双后端逐字一致）；单测 24 项全绿（新增 cfg 求值、$ 词法）。

Added（专门的预处理阶段）

  • 新增独立模块 src/preprocess.rs：编译流水线中专门且唯一的前置处理层，位于 token 收集与语义分析 analyze 之间。收拢源码收集（三级 import 解析 / 循环检测 / 去重）、 逐文件 parse + AST 合并（冲突检测）、语言层 extern/link 结算（魔数校验 / rpath）、 以及 v1.22 的 debug 裁剪到一处。
  • 阶段入口 preprocess::run(src, log, &PreprocessOptions) 返回 PreprocessOutput （program = 裁剪后喂给 analyze 的 AST；raw_program = 裁剪前完整 AST 供 LSP/test）。
  • 扩展点：PreprocessOptions 是预处理行为的唯一配置入口，后续加条件编译（cfg）、 源码宏、特征开关只需加字段 + 一道 pass，build/run/check/test 调用方零改动。
  • frontend() 瘦身为「预处理 → 语义分析」两步编排；跨模块辅助函数以 pub(crate) use 保留原 crate 根路径，toolchain.rs / lsp.rs 零改动。
  • 行为完全不变的架构重构；新增 4 项预处理纯函数单元测试（共 22 项单元测试全绿）， 全量回归通过。

Added（调试输出与调试代码块：编译期裁剪）

  • debug_print(...) 调试输出：print 的调试期别名，输出目标/参数规则/variadic 行为完全一致 （stdout、末尾换行）。debug 构建正常输出；release 构建在语义分析前整句删除。
  • debug { ... } 调试代码块：复用裸块作用域（块内变量块外不可见），debug 构建正常执行 （含副作用）；release 构建在语义分析前整块删除，块内语句（含副作用与资源分配）一概不执行。
  • 编译期裁剪 pass（semantic::strip_debug_program）：仅在 release 构建、且位于 analyze 之前运行——因此 release ① 不检查调试代码类型错误（用户裁决）② 产物零调试字符串/调用残留 ③ 零运行时开销。raw_program 始终保留完整 AST，LSP / dialc test 照常看到全部调试代码。
  • 构建模式映射：默认 --safety debug 保留调试代码；--release / --fast / --safety safe|fast 均裁剪。dialc check 作为纯检查工具始终保留并校验调试代码。
  • 新增 R25 门禁：双后端 debug/release 功能逐字一致、副作用开关、release 产物零字符串残留、 release 跳过类型检查（10 项）。

Added（字段级 ARC：含句柄字段 struct 进容器）

  • 字段级 ARC 落地：含 string / array / map 等句柄字段的 struct 现在可作为数组元素 与 map 值（此前语义层一律拒绝）。装箱为带 desc 表的 ARC box，布局 [desc][rc][payload] （rc 紧邻 payload 以兼容通用 dial_rc_retain(p) 读 p[-1]；desc 在 p[-2]）， 容器释放时按 desc 逐字段级联 release。desc 表 [nfields][(kind,offset)×n] 由两端 静态发射（LLVM 全局常量 / asm .rodata .Ldarc_<Struct>）。
  • 新增 dial_struct_box_arc / dial_struct_box_arc_release（runtime/dial_rt_mem.c）。
  • 容器元素 kind 扩展：数组 DIAL_ELEM_BOXARC=7、map KV_STRUCT_ARC=7；STDLIB_ABI 6→7。
  • 语义层放开数组元素 / map 值 / get_or / 类型良构检查对可装箱 struct 的限制。
  • B6 负向断言翻转为正向；新增 R24 门禁（双后端功能逐字一致 + 20 万次混合压测 + 峰值 RSS < 8MB）。

Fixed（字段级 ARC 收口：双后端级联结算对齐）

  • LLVM get_or 命中 double-free（heap-use-after-free）：命中时 C 侧 dial_kvmap_get_or 对 ARC struct 不 retain，返回的是表内 box 的字段借用；LLVM 变量声明未对解箱副本字段 +1， 作用域退出提前释放字段 → map 销毁二次释放（exit=134）。修复：解箱副本按 desc 递归 retain 字段后再归还 default box（对齐 get 的 borrowed 口径）。
  • LLVM string + 操作数泄漏：dial_string_concat(a,b) 只读不消费操作数，LLVM 端缺失 对 owned 临时（如 str(i)、嵌套拼接）的结算，每轮泄漏一份；补齐与 asm release_string_temp 同口径的操作数释放。修复后 10 万~40 万次压测 RSS 恒定 ~1.5MB。
  • asm KvMap 走通用 dial_rc_release 不逐条释放值装箱：新增 ArcKind::KvMap， retain/release 分派到 dial_kvmap_retain / dial_kvmap_release，与 LLVM release_value 对齐。
  • asm get_or 命中字段 double-release：与 LLVM 同源；补 StructRetain 对解箱副本字段 +1。 （此前被 asm 漏逐条释放 box 掩盖为「仅泄漏」，修 KvMap release 后暴露，已一并修复。）
  • 全部经 ASAN（clang -fsanitize=address，UAF + leak 双检）与双后端 RSS 规模无关性验证。

Fixed（asm 后端 SIMD 功能对等：补齐相对 LLVM 的 3 项缺口）

  • 以双后端实测核实并修复 asm 后端相对 LLVM 的 3 项功能缺口（此前 ROADMAP §5 护栏 称「LLVM 能编译而 asm 拒绝的构造为零」，以 3 个最小用例证伪：LLVM 全部编译运行正确， asm 全部 Fail-Fast 拒绝）：
  • A · SIMD 变量 lane 索引 v[i]（lower.rs:1832 旧版仅接受整数字面量）：字面量走 原快速路径（既有 .s 逐字节零回归）；运行期索引新增动态路径——lower 索引 → 无符号 ICmp Lt(idx, N) 边界检查（对齐 LLVM emit_bounds_check 的 ULT 口径，负数位模式 巨大自然被拦截）→ 越界调 dial_bounds_fail 当场 trap → 正常则 idx*8 动态 PtrAdd
    • Load。双后端合法索引逐值一致、越界都非零终止（LLVM SIGTRAP / asm SIGILL + 诊断）。
  • B · bitcast 到 simd 类型（lower.rs:3665 旧版直接拒绝）：位宽口径改为 N × 元素原生宽度 × 8（对齐 LLVM <N x T> 的 get_abi_size×8，与布局内建同源）； simd 值是栈段指针，simd↔simd 同为 Ptr 走恒等零拷贝返回，跨元素位重解释与 LLVM 逐值一致（simd<int,4>→simd<float,4> 输出 0.000000、→simd<byte,32> 输出 1）。 加类界限「simd 只能 simd↔simd」，与 LLVM 把向量归为聚合、拒绝向量↔整数/指针同口径。
  • C · bitcast 到 array 类型（lower.rs:3666 旧版直接拒绝）：array 是 8 字节不透明 句柄（LLVM 侧擦除为 i8ptr），位宽按 64 计；array↔array（同 Handle）走恒等返回， array↔整数/指针走既有位重解释路径，与 LLVM ptrtoint/inttoptr 语义一致。
  • 新增 R23 门禁：综合正向（变量索引 + bitcast simd/array + 跨元素位重解释）双后端逐值 一致、越界 Fail-Fast 双后端非零终止、O0-O3 四级别输出一致。AArch64 发射经检视正确 （本地交叉汇编受工具链基线限制，与既有 golden 同口径）。

Fixed（P0：ARC 泄漏，两个独立根因）

  • 以资深程序员视角压测发现并修复两类 ARC 泄漏（审查报告初判「异常路径泄漏、LLVM 因 throw 漏更多、语言层通病」，经精细对照实验证明归因有误，真实是两个独立 bug）：
  • A · asm 后端 release_locals_upto 全局 moved 污染：出口（return/throw/break/ continue/goto）释放局部时把编译期 Local.moved=true，该标记被条件分支的 else→merge 正常落穿路径继承，令其 leave_scope/release_scope 误以为已释放而 跳过 → 每个条件出口泄漏一份 try/块作用域 ARC 局部。修复：出口释放不再写 moved； leave_scope 在已终止块（出口路径）跳过 release_scope，正常落穿路径照常释放， 两条 CFG 路径互斥、无需全局标记。实测条件 throw 5000 次 6.3MB→2.0MB、条件 return 6.5MB→2.0MB，无 double-free。
  • B · LLVM 后端字符串字面量堆分配泄漏：Expr::StringLit 每处求值都 dial_string_new（malloc+strlen+memcpy，rc=1），而 StringLit 不在 yields_borrowed_ref、concat 等又不释放右操作数 → 每个字面量每次求值泄漏一份 （s = s + "x" 每轮漏一个 "x"）。修复：新增 immortal_string_lit，生成 [rc=INT64_MIN][len][data][\0] 的 rodata 全局常量、句柄指向 +8 len 字段，与 asm 后端 .Ldstr 完全同构（zero alloc / zero release）。实测百万次拼接 36MB→3.8MB。
  • 新增 R22 门禁：双后端压测用例 + 峰值 RSS 断言（修复版 ~2MB，泄漏版 >20MB）， 无 GNU time 平台退化为功能冒烟。双后端字符串语义（比较/map 键/数组 COW/插值/ 方法/传参返回）逐项一致。

Added（真实 GPU 合成后端）

  • 真实 GPU 合成：补齐 §41 四项缺口中最后一项。用户裁决「继续」（最小破例 + Linux 真合成、其余平台降级）。只破例「运行时 dlopen EGL/GLES 做离屏合成」一条， 其余宪法（零链接期符号、无反向回调、逐像素 CRC 确定、旧 ABI 冻结）原样保留。
  • C 层 packages/gui/src/dial_gui_platform.c 追加 6 个 dial_gui_gpu_real_* API （available / backend / caps / composite / last_exact / degrade_reason）， 旧 9 个 dial_gui_gpu_* 行为一字不动（仍被 AA 组 30 条钉值断言覆盖）。
  • Linux EGL 1.5 surfaceless + GLES2 恒等 shader：framebuffer 上传纹理 → 离屏 FBO → glReadPixels 读回逐字节校验，绝不写源像素（CRC 不漂移）；CLAMP_TO_EDGE + NEAREST 支持 NPOT 任意尺寸；headless 下靠 Mesa 软件渲染可跑通。
  • 软降级：dlopen/初始化/合成不精确一律返 -2（不写错误槽），缺库不导致加载失败； DIAL_GUI_GPU_FORCE_DEGRADE=1 可强制降级路径；Windows/macOS 条件编译恒 -2（未实机）。
  • 三平台 .a 重建，Windows .a 零 dlopen/dlsym 依赖；契约审计 344 → 350 个签名 （343 OO + app_new + 6 第19层），abi=6/version=1.10.0 不变。
  • 门禁 R21：能力自适应双后端用例（有软件 GPU 验证逐字节精确 + 源 CRC 不变，无则验证 降级），强制降级双后端用例；README 新增 §38.24.7、§41 未实现清单同步移除本项。

Added（C → Dial 反向回调）

  • C → Dial 反向回调：补齐 §41 长期标注的「C → Dial 反向回调」缺口， 推翻 GUI 层「绝不反向回调」旧宪法（用户明确裁决），但保留内存底线： 仍无闭包（具名函数 + 显式 rawptr<void> state）、回调参数/结果限标量、 回调线程绝不触碰非原子 ARC 对象（复杂数据走 channel<T>）。
  • C 运行时 stdlib/dial_callback.{h,c}：mutex 保护的注册表 id → {thunk, state, result, done}；dial_callback_register / dial_callback_fire_sync / dial_callback_thread_fire（平台线程 sleep 后主动回调）/ dial_callback_join / dial_callback_result / dial_callback_done / dial_callback_wait / dial_callback_free / dial_callback_count。
  • 类型 callback（不透明句柄）+ 内建 callback / callback_fire / callback_thread / callback_result / callback_done / callback_wait / callback_free / callback_count。
  • 回调入口签名强制 fn(rawptr<void>, int): int；静态 thunk __dial_cb_thunk_<fn> 经 argcell 三槽（payload / state / result 回写）转发，双后端同源、零 ABI 分叉。
  • state 真实透传：入口可 ptr_cast 后读写其裸内存（R20 正向用例 100+7=107）。
  • Fail-Fast：入口签名不符 / state 非 rawptr<void> 编译期拒绝；未注册 id fire 当场终止。
  • 门禁 R20：同步 / 平台线程 / state 透传双后端一致 + 4 项负向拒绝，DIALC_STDLIB_DIR 强制源码回退编入新 C 运行时。README 新增 §32.7、两处「未实现」清单同步更新。

Added（协作式线程池 / 协程 / async-await）

  • 线程池 / 有栈协程 / async-await：补齐 §41 长期标注的「无线程池 / 无异步」缺口， 实现「够用即可」的协作式并发。严格延续三条宪法铁律：无闭包（入口一律具名函数 + 显式 argcell）、无用户可见可变全局状态（句柄显式 new→use→join/close/free）、无用户可见 原子类型（内部同步用 pthread mutex+cond，C 私有）。
  • C 运行时 stdlib/dial_async.{h,c}：POSIX <ucontext.h> / Windows Fiber 有栈协程 （yield 可在任意调用深度发生，局部变量与 ARC 引用随栈帧保留）+ 有界线程池（固定 worker + 任务队列）+ 单线程协作式 async executor（round-robin resume，await 即让出）。
  • 类型：threadpool / coroutine / task（不透明句柄，显式管理，不受 ARC）。
  • 线程池内建：threadpool(n) / pool_submit(pool, fn, args...) → task / task_wait / task_result / task_free / pool_join / pool_close。
  • 协程内建：coroutine(fn, args...) / co_resume → bool / co_yield / co_status / co_free。
  • async 语法：async fn 声明 + await task 表达式（结果恒为 int，复杂结果走 channel， 符合 CSP 宪法）。spawn_async / run_all 驱动协作调度。
  • 双后端同源：asm 与 LLVM 均复用 spawn 的 argcell + 静态 __dial_task_thunk_<fn> 机制（slot[0]=result，slot[1..]=形参），零 ABI 分叉。顺带修复 spawn 无参入口 thunk 的 rdi 丢失隐患（params 恒为单个 void* cell）。
  • Fail-Fast：await 只能在 async fn 内、co_yield 只能在 async fn 内、任务入口返回类型 静态校验（pool/spawn 入口须 int、coroutine 入口须 void）、无 struct 形参。 回归见 tests/run_tests.sh R19 段（双后端一致 + 4 项负向）；C 运行时独立 smoke 见 tools/ 开发期验证。
