[v0.96] — 2026-10-31

本版补齐 ARCHITECTURE.md §8 实现路线 的阶段 2 剩余部分与阶段 5： 包的来源不再只能是本地文件，也可以是 URL；并新增一键安装脚本， 把「装好 Dial 环境 + 把该装的包装上」变成一条命令。

至此路线图 7 个阶段已完成 1 / 2 / 3 / 4 / 5， 剩余阶段 6（Windows 线程后端）与阶段 7（官方标准库 .dialpkg 化）。

Added（新增）

  • dialc install <URL>（阶段 2）：包可以直接从 URL 装，不用先手动下载。
  • 只允许 https://（本机 localhost / 127.0.0.1 / ::1 例外，供本地镜像与自测）。 明文 http 能被中间人改写，而 SHA256 挡不住「换了内容还带着正确哈希」的伪造， 因此非本机地址一律拒绝——宁可装不上，也不降级到明文。
  • --sha256 <哈希>：钉死整个下载物的哈希，用来证明「这就是我要的那一份包」。 比对发生在解压之前，不符即失败；下载物随即删除。
  • 没给 --sha256 也能装，但会明确提示这次只验了「包内文件与 manifest 是否一致」 （能发现残缺与篡改），没验整包来源——不静默降级。
  • 下载用外部 curl 而非引入 Rust 的 HTTP 库：编译器本来就依赖外部工具链 （zig cc / clang / ar），下载器属同一类依赖，不新增「运行期还要装个东西」的负担； 引入 TLS 栈（rustls 等）会显著拉长编译时间与依赖树，与 §21「不引入无用依赖」相悖。 TLS 绝不手写——证书校验、主机名校验、重定向全部交给 curl 背后的成熟实现。
  • 临时文件成功失败都删，~/.dial/packages/ 里不留残骸。
  • 解压前整包校验（阶段 2 的安全底座，src/package.rs::verify_archive）： 按包内 manifest.txt 登记的 SHA256，把包里每个文件验一遍， 一个字节都还没落到磁盘——这是 ARCHITECTURE.md §5.1「校验先于一切 / 每个文件都要校验」 的字面实现。此前 dialc install（本地文件）完全不做校验， 哈希只在编译时对用到的那两个文件验；现在安装这一步就拦下了。 未在 manifest.txt 登记哈希的文件一律拒绝——无法校验的文件不允许进入缓存。
  • 一键安装脚本（阶段 5）：tools/install-dial.sh（Linux / Termux）与 tools/install-dial.ps1（Windows / PowerShell）。按 §3.2 承担两件事（顺序不能反）： 1. 初始化 Dial 环境：建 ~/.dial/ 目录树（bin / packages / cache/downloads）、 把 dialc 装进 ~/.dial/bin/ 并挂进 PATH、把 stdlib/ 与 runtime/ 一并装到 ~/.dial/、写一份 ~/.dial/config.txt 工具链配置； 2. 自动安装已下载的包：初始化完成后重新扫描找到的 .dialpkg （当前目录及其子目录，或参数指定的目录），逐个执行 dialc install。

    为什么脚本要「自动重新扫描」而不是让用户逐个点名：一键安装的语义是 「我把这个目录交给你，你把该装的都装上」。用户不该需要记住包名、也不该需要 为每个包敲一条命令——包就在那里，脚本看得见。

Fixed（修复）

  • 一键安装后编译器找不到 stdlib/ 与 runtime/：编译器按可执行文件所在位置 向上找这两个目录（target/release/dialc → 工程根）。装到 ~/.dial/bin/dialc 后， 那个位置正好是 ~/.dial/——所以它们必须跟着一起装。 少了这一步，用户在自己项目里编译会报「找不到 stdlib/ 与 runtime/ 目录」， 一键安装等于没装。脚本现已一并安装这两个目录。
  • install 时的 manifest.txt 校验时机：此前 install() 先解压再校验（且当时压根没校验）， 现在先校验后解压。

Added（测试）

  • 测试组 L（tests/pkg_install_url.py，26 项断言）：真起一个本机 HTTP 服务器 真实提供 .dialpkg，用真正的 dialc install <URL> 去装，验证：
  • 正常安装成功；--sha256 与实际一致时也成功；未钉死哈希时给出明确提示；
  • 坏包一律装不进去：内容被篡改（改 .diali 但保留原哈希）、 --sha256 不符、404、非本机的明文 http——四种情形全部失败；
  • 失败后 ~/.dial/packages/ 无残骸（半截的包绝不能留在缓存里）；
  • 装完能 import 并编译运行，输出正确；
  • 一键脚本：初始化出编译器 + stdlib/ + runtime/ + 配置， 自动扫描并装上 .dialpkg，最后在与 Dial 源码树无关的独立项目目录里 用装好的编译器编译 import 程序并运行——这是「一键安装」的意义所在。 全部用例在隔离的 HOME 下运行，不碰用户真实缓存。
