Added（C → Dial 反向回调）

  • C → Dial 反向回调：补齐 §41 长期标注的「C → Dial 反向回调」缺口， 推翻 GUI 层「绝不反向回调」旧宪法（用户明确裁决），但保留内存底线： 仍无闭包（具名函数 + 显式 rawptr<void> state）、回调参数/结果限标量、 回调线程绝不触碰非原子 ARC 对象（复杂数据走 channel<T>）。
  • C 运行时 stdlib/dial_callback.{h,c}：mutex 保护的注册表 id → {thunk, state, result, done}；dial_callback_register / dial_callback_fire_sync / dial_callback_thread_fire（平台线程 sleep 后主动回调）/ dial_callback_join / dial_callback_result / dial_callback_done / dial_callback_wait / dial_callback_free / dial_callback_count。
  • 类型 callback（不透明句柄）+ 内建 callback / callback_fire / callback_thread / callback_result / callback_done / callback_wait / callback_free / callback_count。
  • 回调入口签名强制 fn(rawptr<void>, int): int；静态 thunk __dial_cb_thunk_<fn> 经 argcell 三槽（payload / state / result 回写）转发，双后端同源、零 ABI 分叉。
  • state 真实透传：入口可 ptr_cast 后读写其裸内存（R20 正向用例 100+7=107）。
  • Fail-Fast：入口签名不符 / state 非 rawptr<void> 编译期拒绝；未注册 id fire 当场终止。
  • 门禁 R20：同步 / 平台线程 / state 透传双后端一致 + 4 项负向拒绝，DIALC_STDLIB_DIR 强制源码回退编入新 C 运行时。README 新增 §32.7、两处「未实现」清单同步更新。

Added（协作式线程池 / 协程 / async-await）

  • 线程池 / 有栈协程 / async-await：补齐 §41 长期标注的「无线程池 / 无异步」缺口， 实现「够用即可」的协作式并发。严格延续三条宪法铁律：无闭包（入口一律具名函数 + 显式 argcell）、无用户可见可变全局状态（句柄显式 new→use→join/close/free）、无用户可见 原子类型（内部同步用 pthread mutex+cond，C 私有）。
  • C 运行时 stdlib/dial_async.{h,c}：POSIX <ucontext.h> / Windows Fiber 有栈协程 （yield 可在任意调用深度发生，局部变量与 ARC 引用随栈帧保留）+ 有界线程池（固定 worker + 任务队列）+ 单线程协作式 async executor（round-robin resume，await 即让出）。
  • 类型：threadpool / coroutine / task（不透明句柄，显式管理，不受 ARC）。
  • 线程池内建：threadpool(n) / pool_submit(pool, fn, args...) → task / task_wait / task_result / task_free / pool_join / pool_close。
  • 协程内建：coroutine(fn, args...) / co_resume → bool / co_yield / co_status / co_free。
  • async 语法：async fn 声明 + await task 表达式（结果恒为 int，复杂结果走 channel， 符合 CSP 宪法）。spawn_async / run_all 驱动协作调度。
  • 双后端同源：asm 与 LLVM 均复用 spawn 的 argcell + 静态 __dial_task_thunk_<fn> 机制（slot[0]=result，slot[1..]=形参），零 ABI 分叉。顺带修复 spawn 无参入口 thunk 的 rdi 丢失隐患（params 恒为单个 void* cell）。
  • Fail-Fast：await 只能在 async fn 内、co_yield 只能在 async fn 内、任务入口返回类型 静态校验（pool/spawn 入口须 int、coroutine 入口须 void）、无 struct 形参。 回归见 tests/run_tests.sh R19 段（双后端一致 + 4 项负向）；C 运行时独立 smoke 见 tools/ 开发期验证。

Added

  • 显式独占所有权 own var（开发中）：新增 own 关键字，own var x: T = e; 把编译期自动推断的 Move 策略升级为程序员显式声明的独占转移——强制接管即转移 （use-after-move 编译期报错）、离开作用域确定 drop、只能修饰拥有资源的类型。 刻意不引入借用检查器（无 &T / 生命周期 / 别名分析）。语义层强制 move_hint 与 mark_moved，asm / LLVM 两后端复用既有 Move 路径、代码生成零分叉。 回归见 tests/run_tests.sh R12b 段。

Fixed / Added（方案 C：完整 consume 体系）

  • 修「假 move」——own 转移零开销承诺落空（P0）：程序员视角对抗测试发现 asm 后端 need_retain = is_copy || (borrowed && !move_hint) 中 is_copy 对 Expr::Var/Field/Deref 恒为 true，短路了 move_hint，导致 own 转移与普通「最后引用 move」都仍 emit retain （实测 own 转移 retain=1，与 LLVM 普通绑定无差异）。对齐 LLVM if !move_hint 改为 need_retain = !move_hint && (is_copy || borrowed)。实测 retain 计数：普通 move 1→0、 own move 1→0、三变量链 2→0，release 恒为 1。顺带修好普通变量 move 优化在 asm 侧长期失效。
  • 修「单向独占」——own 可被静默别名（P0）：own 变量被普通 var 接管时源未标 moved， 之后仍可用，own 退化为普通 var。新增完整 consume：sema check_moved_stmt 在 own 声明接管 源、或 own 变量被赋值给他人时当场 mark_moved 源；set_moves 中源是 own 则强制 move_hint=true（新增 collect_own_names 从 AST 收集 own 集合）。sema moved 与 lowering move_hint 两套记账严格配对，避免 double-free。实测 own→别名→返回 10 万次 RSS 稳定。
  • own 函数参数：fn f(own x: T) 声明 consume 形参（AST Func.own_params / FuncInfo.own_params 与 params 一一对应）。调用点 sema 对实参 mark_moved、两后端 lowering/gen_call 标 Local.moved 并让被调方入口跳过 +1 retain（退出 -1 release），所有权从调用方转移到被调方。 own 标量参数 / own 默认参数 / own struct 字段均 Fail-Fast 拒绝（后者因 Dial struct 值语义 无法维持字段独占）。普通参数语义零回归。回归见 tests/run_tests.sh R12c 段（新增 13 项）。
