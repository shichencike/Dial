# Dial for VS Code（v1.04）

给 `.dial` 文件提供：

1. **保存即报诊断**——走的是编译器自己的词法/语法/语义，因此绝不会出现「编辑器说能过、编译器说不能过」。
   诊断带**稳定错误码**（`dialc.lex` / `dialc.parse` / `dialc.sema` / `dialc.package.missing`），
   定位落在出错的那条语句上。
2. **语义高亮**——token 由编译器自己的词法器产出，高亮与编译用的是同一份词法，不会慢慢分道扬镳。
3. **导航与编写辅助**——大纲、引用查找、重命名、签名帮助、保守格式化、参数 inlay 提示。
4. **高级交互**——代码动作（缺包时直接给「安装这个包」）、折叠、选择范围、文档链接（`import` 可跳转）。

> 安装包：`dial-1.4.0.vsix`（见各版本 GitHub Release，或本地 `bash editors/vscode/build.sh` 现构建）。
> 跑一键安装脚本（`install-dial.sh` / `install-dial.ps1`）时也会**自动下载并装上**这个插件。

## 能力清单

| 能力 | 说明 |
| --- | --- |
| 诊断 | 只报第一个错误（与 `dialc build` 同因同位置），带稳定错误码 |
| 语义高亮 | 关键字 / 字符串 / 数字 / 运算符 / 变量 / 类型 |
| Hover | 类型 + 声明片段；包符号显示 `.diali` 文档 |
| 跳转定义 | 文件内精确跳转；包符号跳到 `.diali` 声明行 |
| 补全 | 作用域可见符号；`textEdit` 精确替换范围、`sortText` 排序、`.` 触发 |
| 文档符号 | 大纲递归到局部变量，可在面包屑里跳转 |
| 工作区符号 | 跨已打开文件与已加载包，按名字子串搜索 |
| 引用查找 | 含声明；同名遮蔽天然正确（内层同名变量不会被并入外层） |
| 重命名 | 先 `prepareRename` 确认可改区间，再一次性改全 |
| 签名帮助 | `(` / `,` 触发，显示完整签名与各参数标签 |

| 选择范围 | 从光标处逐级向外：表达式 → 语句 → 块 → 函数 |
| 文档链接 | `import "pkg";` 可点击跳到该包的 `.diali` |

## 安装

这个扩展**不需要 npm install**（没有第三方依赖，LSP 客户端是手写的）。

```bash
# 方式一：侧载 .vsix（推荐，来自 Release 或本地构建）
code --install-extension dial-1.4.0.vsix

# 方式二：直接拷进扩展目录（改完源码可立刻生效）
mkdir -p ~/.vscode/extensions/dial-lang.dial-1.4.0
cp -r /path/to/dialc/editors/vscode/* ~/.vscode/extensions/dial-lang.dial-1.4.0/
# 重启 VS Code

# 方式三：开发模式——VS Code 里打开本目录，按 F5 启动「扩展开发宿主」
```

前置条件：`dialc` 在 `PATH` 里，且版本 **≥ v0.98**（要支持 `lsp` 子命令）。
不在 PATH 里也行，改设置里的 `dial.lsp.path` 指到绝对路径。

> 如果你的 `dialc` 是动态链接本机 LLVM 的（如 `libLLVM.so.18.1rc`），需要先让加载器找得到它，
> 例如 `export LD_LIBRARY_PATH=/path/to/llvm/lib`。启动失败时看「输出 → Dial Language Server」面板。

## 设置

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| `dial.lsp.path` | `dialc` | 编译器路径 |
| `dial.lsp.trace` | `false` | 把协议收发打到输出面板（排障用） |

## 已知限制

说清楚边界，比事后让人来问「为什么这儿不对」好：

- **语义错误的定位精确到语句级**，不是表达式级——表达式（`Expr`）目前不带位置信息。
  好在错误会落在**出错的那条语句**上，而不是文件开头（旧行为），定位成本已经大幅下降。
- **格式化是保守的**：只去行尾空白、保证末尾恰有一行换行，**不做重排/换行**。
  Dial 没有官定代码风格，激进格式化只会误伤对齐敏感的代码。
- **inlay 提示只标形参名**（`a: `），不标类型：索引独立于类型检查，半成品代码拿不到类型，
  硬标会给出错的类型——那比不标更糟。
- **重命名只作用于当前 `.dial` 文件**：Dial 是单文件编译；包符号（`.diali`）**只读**，不重命名。
- **补全不含类型推断**：补全项的类型来自显式声明与已索引的签名。
- **Windows 上 `LLVM-C.dll` 必须与 `dialc.exe` 同目录**，否则启动时加载失败。
- **不支持多根工作区**：工作区符号只搜「已打开的文件 + 已加载的包」。

## 为什么不用 `vscode-languageclient`

官方客户端库更完备，但要拉一整棵 npm 依赖树。本扩展真正要做的只有四件事：
起进程、转发文档变化、收诊断、转发语义 token。手写这 200 行换来的是
**拷进目录就能用，不需要 Node / npm / 联网**。对一门语言的第一版编辑器支持来说，
「装得上」比「功能全」重要。

## 其它编辑器

任何支持 LSP 的编辑器都能接，只需要它去启动 `dialc lsp`。本仓库已附带：

- **Neovim**：[`../neovim/README.md`](../neovim/README.md)（零依赖，内置 LSP 客户端）
- **Emacs**：[`../emacs/README.md`](../emacs/README.md)（`eglot` 原生连，只加几行 `init.el`）

其它编辑器（JetBrains / Zed / Sublime 等）照各自文档把 `dialc lsp` 配成 LSP server 即可，
不再单独维护插件。
